# 数据来源模式说明（Data Source Modes）

## 概述

`szabot-file-editor` 支持三种数据来源模式，以及它们的混合组合。Agent 需要在执行填写前先识别用户属于哪种模式。

## 模式 A：影库项目查询

### 触发特征

- 用户提到了一个影库项目名称（如"庆余年第三季"、"逐玉"等）
- 用户说"用XX项目的信息填写"、"查一下XX然后填表"
- 用户没有直接提供数据内容，而是期望 Agent 去查询

### 执行方式

调用 `szabot-copilot` 技能查询项目详细信息，获取结构化数据。

> ⚠️ **必须按以下两步执行，禁止在第一次搜索后就直接进入模版填写流程。**

#### Step 1：搜索并识别主要项目

1. 用项目名称进行**模糊搜索**，获取搜索结果列表
2. **审查搜索结果**：如果返回了多个项目（如同名的电视剧、电影、综艺、网剧等），**必须识别出主要项目**：
   - **优先选择电视剧/剧集类型**的项目（模版填写场景中电视剧最常见，如首集表、审批表等通常针对电视剧）
   - 如果有多个同类型项目，优先选择管理状态为"进行中"或最近更新的项目
   - 如果仍无法确定，**必须询问用户**确认具体是哪个项目，不要自行猜测
3. 确定主要项目后，**记录其项目 ID**，用于下一步全量查询

#### Step 2：获取项目全量字段

1. 使用确定的项目 ID，**再次查询该项目的全部可用字段**
2. 查询的 `target` 字段范围应**尽可能全面**，不要仅使用第一次搜索返回的有限字段
3. 建议的全量字段查询范围（根据模版需要动态调整）：
   - 基础信息：项目名称、类型、集数、单集时长、题材、制式、剧集分类等
   - 人员信息：导演、编剧、主要演员、制片人、总制片人、执行制片人等
   - 公司信息：出品公司、制作公司、联合出品方、承制方等
   - 进度信息：开机日期、杀青日期、预计上线日期、播出时间等
   - 内容信息：故事梗概、项目简介等
   - 其他信息：管理状态、豆瓣评分、腾讯最高热度值等
4. **只有在获取到全量字段数据后**，才能进入 Phase 3（模版解析）和 Phase 4（智能映射）

> **❌ 错误做法**：第一次模糊搜索返回了项目名称、导演等少量字段后，就直接开始准备 fill_data.json 填写模版
>
> **✅ 正确做法**：第一次搜索确认项目身份和项目 ID → 用项目 ID 查询全量字段 → 获取到完整数据后再进入模版解析和填写流程

### 常见需要获取的字段

| 字段类别 | 示例字段 |
|---------|---------|
| 基础信息 | 项目名称、类型、集数、单集时长、题材、制式 |
| 人员信息 | 导演、编剧、主演、制片人 |
| 公司信息 | 出品方、制作方、联合出品方 |
| 进度信息 | 开机日期、杀青日期、预计上线日期 |
| 财务信息 | 总投资额、单集成本 |

> ⚠️ 具体需要查询哪些字段，应根据模版中的待填字段动态确定。建议先解析模版，再有针对性地查询。

## 模式 B：用户文本输入

### 触发特征

- 用户在消息中直接给出了待填写的数据
- 用户说"帮我把以下信息填入"、"按照这些内容填写"
- 数据可能是结构化的（key: value 格式），也可能是非结构化的自然语言

### 执行方式

由 Agent（LLM）直接从用户文本中提取 key-value 数据。

### 处理策略

**结构化输入**：
```
项目名称：庆余年第三季
导演：孙皓
编剧：王倦
```
→ Agent 直接提取为 key-value 字典

**非结构化输入**：
```
这是一个由孙皓执导、王倦编剧的古装剧，叫庆余年第三季，预计40集...
```
→ Agent 用语义理解能力提取关键信息

**信息不完整时**：
→ 先填写能匹配的字段，再汇总缺失字段询问用户补充

## 模式 C：内容文件 + 模版文件

### 触发特征

- 用户提供了两个文件
- 用户说"用文件A填写文件B"、"参考这个文件填写模版"
- 一个文件包含数据，另一个是待填写的模版

### 执行方式

1. **文件角色识别**：区分哪个是数据源、哪个是模版
2. **内容文件解析**：使用 `content_extractor.py` 提取结构化数据
3. **归一化**：将提取的数据转为统一格式

### 文件角色识别规则

| 判断依据 | 数据源文件特征 | 模版文件特征 |
|---------|--------------|------------|
| 文件名 | 含"资料"、"信息"、"数据" | 含"模版"、"模板"、"表格"、"审批" |
| 内容 | 大量实际数据 | 大量空白/占位符 |
| 用户说明 | "用这个文件的内容" | "填写这个模版" |

> 如果无法判断 → 询问用户："哪个是模版文件，哪个是内容文件？"

### 内容文件解析命令

```bash
cd {skill_base_dir}/scripts && python3 content_extractor.py /path/to/content_file.xlsx
```

## 混合模式

三种模式可以混合使用：

| 混合场景 | 处理策略 |
|---------|---------|
| **A + B** | 先查询项目信息，再用用户文本覆盖/补充 |
| **B + C** | 先解析内容文件，再用用户文本覆盖/补充 |
| **A + C** | 先查询项目信息，再用内容文件数据覆盖/补充 |

### 数据合并优先级

```
用户直接输入的文本（模式 B） > 用户上传的内容文件（模式 C） > 系统查询的项目信息（模式 A）
```

**原则**：用户显式提供的信息永远优先于系统自动获取的信息。

## 统一数据格式（Normalized Data Dict）

无论数据来自哪种模式，都归一化为以下格式：

```json
{
  "source_mode": "A",
  "source_description": "影库项目查询：庆余年第三季",
  "data": {
    "项目名称": "庆余年第三季",
    "导演": "孙皓",
    "编剧": "王倦",
    "主演": ["张若昀", "李沁", "吴刚"],
    "集数": 40,
    "单集时长": "45分钟"
  },
  "unmapped_raw": "",
  "confidence": {
    "项目名称": 1.0,
    "导演": 1.0
  }
}
```

此格式由 Agent 在内存中构建，不需要脚本输出。
