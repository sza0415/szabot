# 文件上传与下载工作流（File Upload & Download Workflow）

## 概述

本工作流包含两个核心能力：

1. **文件上传**：将本地文件上传到影库文件系统，获取系统生成的 `fid`（文件唯一标识）
2. **获取下载链接**：根据 `fid` 获取文件的下载/预览 URL，用于将文件下载到本地进行编辑

这两个能力是 `szabot-file-editor` 的基础设施，为后续的模版解析和填写提供文件 I/O 支持。

## 全局执行规则

1. **自动化优先**：尽量自动从上下文中获取文件路径、fid 等信息，减少向用户提问。
2. **fid 是系统生成的**：`fid` 由上传接口返回，**严禁使用用户口头提供或手动输入的 fid**。
3. **支持任意文件类型**：对文件格式没有限制，任何文件都可以上传。
4. **脚本路径**：
   - 上传脚本：`{skill_base_dir}/scripts/upload_file.py`
   - 下载链接脚本：`{skill_base_dir}/scripts/download_url.py`（仅用于下载文件到本地编辑的场景）
5. **结果持久化**：上传成功后，必须将 `fid` 和完整返回信息保留在对话上下文中，确保后续工作流可以直接引用。
6. **上传后的输出规则**：
   - **原模版文件、解析结果文件、填写数据文件**：上传后只需在回复中展示 `fid`，不需要调用 `download_url.py` 获取下载链接
   - **填写结果文件**：上传后使用 `bvnext://x-callback-url/doc?fid=<fid>` 格式生成链接，以 `[结果文件](bvnext://x-callback-url/doc?fid=<fid>)` 格式输出给用户

## 能力一：文件上传

### 触发场景

- 用户提供了本地文件，需要上传到影库文件系统
- 后续工作流需要 `fid`，但上下文中尚无合法 `fid`
- 填写完成的模版文件需要上传回影库系统

### Step 1 — 获取文件路径

**目标**：确定待上传的本地文件路径。

**信息来源**（按优先级）：
1. 用户在对话中直接提供了文件路径
2. 用户通过 IDE 上传/附加了文件（从上下文提取路径）
3. 用户提到了文件名，可在工作区中搜索定位

**校验清单**：

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| 文件存在 | 路径有效且文件存在 | 提示用户确认路径 |
| 路径格式 | 必须使用绝对路径 | 自动转换为绝对路径 |

### Step 2 — 执行上传

**执行命令**：

```bash
cd {skill_base_dir}/scripts && python3 upload_file.py /absolute/path/to/file.pdf

# 自定义上传文件名（推荐）
cd {skill_base_dir}/scripts && python3 upload_file.py /tmp/filled_file.xlsx --name "首集表_填写结果_1713250800.xlsx"
```

> ⚠️ 文件路径必须使用**绝对路径**。
> ⚠️ 推荐使用 `--name` 参数指定有意义的上传文件名（不传则使用本地文件的原始文件名）。

**上传文件名命名规则**：

| 场景 | 命名规则 | 示例 |
|------|---------|------|
| 原模版文件 | 使用原始文件名 | `首集表.xlsx` |
| 填写结果文件 | `{原文件名}_填写结果_{时间戳}.{ext}` | `首集表_填写结果_1713250800.xlsx` |
| 解析结果文件 | `{原文件名}_解析结果_{时间戳}.json` | `首集表_解析结果_1713250800.json` |
| 填写数据文件 | `{原文件名}_填写数据_{时间戳}.json` | `首集表_填写数据_1713250800.json` |

> 💡 时间戳使用 Unix 时间戳（秒级），可通过 `date +%s` 获取。

**标准输出**（JSON 格式）：

```json
{
  "fid": "fid_xxxxxxxxxxxxxxxxxxxxxxxx",
  "name": "首集表_填写结果_1713250800.xlsx",
  "size": 1048576,
  "md5": "5f81b9b77acd-cf6bce182ee6cfa33dfd",
  "mimeType": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
  "fileType": "excel",
  "uploadName": "首集表_填写结果_1713250800.xlsx"
}
```

**关键字段说明**：

| 字段 | 说明 |
|------|------|
| `fid` | 文件唯一标识，**由系统生成**，后续获取下载链接的必要参数 |
| `name` | 原始文件名 |
| `size` | 文件大小（字节） |
| `md5` | 文件内容 MD5 校验值 |
| `mimeType` | 文件 MIME 类型 |
| `fileType` | 文件类型分类（`pdf` / `word` / `excel` / `ppt` 等） |
| `uploadName` | 上传文件名（由 `--name` 参数指定，或默认使用本地文件名） |

### Step 3 — 结果处理

#### 上传成功（退出码 = 0）

1. 从标准输出 JSON 中提取 `fid` 及完整信息
2. **将 `fid` 和完整返回信息保留在上下文中**
3. 向用户展示上传结果摘要

#### 上传失败（退出码 ≠ 0）

| 退出码 | 含义 | 处理方式 |
|--------|------|---------|
| `1` | 文件不存在 | 提示用户检查文件路径 |
| `2` | 其他错误（接口异常等） | 查看 stderr 输出，展示错误详情 |

## 能力二：获取文件下载链接

### 触发场景

- 上下文中已有 `fid`，需要获取文件的下载 URL 以便下载到本地进行编辑
- 模版文件已上传到影库系统，需要下载到本地进行解析和填写

### 前置条件

- 上下文中必须有通过**上传流程**获取的合法 `fid`
- **严禁使用用户口头提供或凭空编造的 fid**

### Step 1 — 执行获取下载链接

**执行命令**：

```bash
cd {skill_base_dir}/scripts && python3 download_url.py fid_xxxxxxxxxxxxxxxxxxxxxxxx
```

**标准输出**（JSON 格式）：

```json
{
  "fid": "fid_xxxxxxxxxxxxxxxxxxxxxxxx",
  "download_url": "https://cdn-example.com/ai/file/download?id=xxxxx&token=yyyyy",
  "name": "模版文件.xlsx",
  "size": 1048576,
  "mimeType": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"
}
```

> ⚠️ **注意**：`download_url` 的值是由服务端接口返回的真实下载链接（包含 `?q-sign-algorithm=...&q-ak=...&q-sign-time=...&q-key-time=...&q-signature=...` 等鉴权参数），格式由服务端决定。Agent **必须原样使用此完整链接**（包含 `?` 后面的所有 query string 鉴权参数），**绝对禁止**：
> - 自行拼接 URL（如 `https://claw.szabot.internal/files/<fid>`）
> - 截断 URL（只使用 `?` 前面的基础路径，丢弃鉴权参数）
> - 修改或重新编码 URL 中的任何部分
>
> 缺少鉴权参数的链接无法正常下载文件。

**关键字段说明**：

| 字段 | 说明 |
|------|------|
| `fid` | 文件唯一标识 |
| `download_url` | 文件下载/预览链接（包含鉴权参数），**必须完整使用**，可直接用于下载文件到本地 |
| `name` | 文件名（如接口返回） |
| `size` | 文件大小（如接口返回） |
| `mimeType` | 文件 MIME 类型（如接口返回） |

### Step 2 — 下载文件到本地

获取到 `download_url` 后，使用 `curl` 或 `wget` 将文件下载到本地临时目录：

```bash
curl -o /tmp/template_file.xlsx "<download_url>"
```

> ⚠️ 下载到本地后，文件路径将作为后续模版解析和填写步骤的输入。

### Step 3 — 结果处理

#### 获取成功（退出码 = 0）

1. 从标准输出 JSON 中提取 `download_url`
2. 下载文件到本地
3. **将下载链接和本地文件路径保留在上下文中**

#### 获取失败（退出码 ≠ 0）

| 退出码 | 含义 | 处理方式 |
|--------|------|---------|
| `1` | 参数错误（未提供 fid） | 检查是否正确传入了 fid |
| `2` | 其他错误（接口异常等） | 查看 stderr 输出，展示错误详情 |

## 典型使用流程

### 场景 1：用户上传本地文件 → 获取 fid → 后续编辑

```
1. 用户提供本地文件路径
2. upload_file.py 上传文件 → 获取 fid
3. fid 保留在上下文中，供后续模版解析使用
```

### 场景 2：上下文中已有 fid → 下载文件 → 本地编辑

```
1. 从上下文获取 fid
2. download_url.py 获取下载链接
3. curl 下载文件到本地临时目录
4. 本地文件路径供后续模版解析和填写使用
```

### 场景 3：编辑完成 → 上传回影库系统

```
1. 模版填写完成，生成新文件
2. upload_file.py 上传填写后的文件 → 获取新 fid
3. 以 [结果文件](bvnext://x-callback-url/doc?fid=<fid>) 格式输出给用户
```

## 与其他工作流的衔接

| 下游工作流 | 用途 | 使用的字段 |
|-----------|------|-----------|
| 模版解析（parse_template） | 解析模版结构，提取待填字段 | 本地文件路径 |
| 内容文件解析（parse_content_file） | 解析数据源文件，提取填写数据 | 本地文件路径 |
| 模版填写（fill_template） | 将数据写入模版 | 本地文件路径 |
| `szabot-project`（草稿关联文件） | 将填写后的文件关联到项目草稿 | `fid` 作为 `file_id` |

> ⚠️ 所有下游工作流中使用的 `fid` **必须来自本上传流程的返回结果**，不可使用用户自行提供的 ID。
