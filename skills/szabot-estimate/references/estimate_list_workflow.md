# 评估单列表查看工作流

> 🚫 **严格使用限制**：本工作流**仅适用于"查看评估单列表"场景**。当且仅当用户明确表达了查看某个项目评估单列表的意图时，才可加载并执行本文件。

---

## 全局执行规则

1. **底层操作静默**：MCP 调用过程不向用户展示，只呈现业务层面的信息。
2. **结构化展示**：以表格形式展示评估单列表，便于用户快速浏览。

---

## Step 1：获取项目 ID

从用户输入中提取项目 ID（`projID`）。

**获取方式（按优先级）：**

1. 用户直接提供了项目 ID（如"查看 3974 的评估单"）
2. 用户提供了项目名称，通过 `kb_search` 查询获取项目 ID
3. 上下文中已有项目 ID（如之前的对话中已确定）
4. 无法确定时，询问用户提供项目 ID 或项目名称

---

## Step 2：调用 listEvaluation 获取列表

> 静默执行，不向用户展示工具名和参数。

```bash
mcporter call szbotprojectformal listEvaluation --args '{"projID": <项目ID>}'
```

**异常处理：**

> 按 `mcp_call_rules.md` §4 的错误分类与重试策略执行。

| 情况 | 错误类型 | 处理 |
|------|---------|------|
| 网络超时 / 后端不可用 | 网络失败 | 自动重试 3 次（2s→4s→8s），全部失败后告知用户 |
| 权限不足 | 权限问题 | 不重试，引导用户检查项目权限 |
| 项目 ID 不存在 | 业务逻辑 | 若用户提供了项目名称 → 自动调用 `kb_search` 获取正确 ID 后重试 1 次；否则提示用户确认 |
| 返回列表为空 | —（非错误） | 告知用户该项目暂无评估单，引导创建 |

---

## Step 3：结构化展示列表

### 3.1 最终展示表结构（标准模板，表头一字不改）

🛑 **强制要求**：最终呈现给用户的**唯一合法表头**如下 7 列，顺序、命名、列数**完全一致**，严禁合并、删减、改名：

```
| 评估单 ID | 项目名称 | 上会主题 | 评估单状态 | 中台评估 | 决策会 | 创建时间 |
```

⚠️ 常见错误（禁止）：
- ❌ 把「评估单状态」与「中台评估」合并为一列叫「当前状态」
- ❌ 把「评估单 ID」渲染为纯文本（未加超链接）
- ❌ 省略「决策会」「创建时间」等列
- ❌ 将所有评估单显示为同一状态（如全部"版权信息评估（处理中）"）——必须按每条数据的真实 `items` 拼接

### 3.2 字段映射表

| 展示字段 | 数据来源 | 说明 |
|---------|---------|------|
| 评估单 ID | `evaluationID` | **必须**渲染为超链接：`[{evaluationID}](https://szgate.szabot.internal/x/r/doto9awl4o?applyId={evaluationID})` |
| 评估名称 | `pname` | 评估名称 |
| 上会主题 | `meetingSubject` | 立项评估 / 开机评估 / 简单报备 等 |
| 评估单状态 | `rocEstimateStates.items` | 评估单各阶段状态。详见下方"状态字段拼接规则" |
| 中台评估 | `middleEstimateStates.items` | 中台评估各阶段状态（制片支持中心、编审&IP 组等）。详见下方"状态字段拼接规则" |
| 决策会 | `meetingName` | 所属决策会名称 |
| 创建时间 | `gmtCreate` | 评估单创建时间 |

**状态字段拼接规则（重要）：**

⚠️ **不要使用 `ridState` 字段**。`ridState` 只是一个标识字段，无法反映评估单的真实多阶段并行状态。

「评估单状态」与「中台评估」两列**独立拼接**，互不合并；列内多项**竖向堆叠**展示（用 `<br>` 换行），避免横向溢出：

- **评估单状态**：遍历 `rocEstimateStates.items`，每项格式化为 `name-state_name`，多项之间用 `<br>` 连接（在表格单元格内换行）
- **中台评估**：遍历 `middleEstimateStates.items`，每项格式化为 `name-state_name`，多项之间用 `<br>` 连接

> ⚠️ 严禁使用「、」「,」「 / 」等横向分隔符。Markdown 表格单元格内的换行**必须使用 `<br>` 标签**（而非 `\n`），否则不会真正换行。

**空值兜底：**
- 若 `rocEstimateStates.items` 为空，「评估单状态」回退使用 `rocEstimateStates.state_name`（如"评估中"）；若 `state_name` 也为空则展示「-」
- 若 `middleEstimateStates.items` 为空，「中台评估」回退使用 `middleEstimateStates.state_name`；若也为空则展示「-」（常见场景：尚未触发中台评估流程）

**示例：**

接口返回：
- `rocEstimateStates.items = [{name:"内容评估", state_name:"评估中"}]`
- `middleEstimateStates.items = [{name:"制片支持中心意见", state_name:"评估中"}, {name:"编审&IP 组意见", state_name:"评估中"}]`

正确的 Markdown 单元格内容（注意 `<br>`）：

```
| 内容评估-评估中 | 制片支持中心意见-评估中<br>编审&IP 组意见-评估中 |
```

最终视觉效果（单元格内竖排堆叠）：

| 评估单状态 | 中台评估 |
|-----------|---------|
| 内容评估-评估中 | 制片支持中心意见-评估中<br>编审&IP 组意见-评估中 |

### 3.3 完整表格示例（直接套用此格式）

**接口返回 3 条评估单时，正确的 Markdown 输出：**

```markdown
| 评估单 ID | 项目名称 | 上会主题 | 评估单状态 | 中台评估 | 决策会 | 创建时间 |
|----------|---------|---------|-----------|---------|-------|---------|
| [10007390](https://szgate.szabot.internal/x/r/doto9awl4o?applyId=10007390) | 江南的杨梅 | 立项评估 | 内容评估-评估中 | 制片支持中心意见-评估中<br>编审&IP 组意见-评估中 | 2026年4月立项会 | 2026-04-21 15:59 |
| [10007380](https://szgate.szabot.internal/x/r/doto9awl4o?applyId=10007380) | 《逐光》 | 立项评估 | 版权信息评估-处理中 | - | 2026年4月立项会 | 2026-04-21 11:38 |
| [10007379](https://szgate.szabot.internal/x/r/doto9awl4o?applyId=10007379) | 江南的杨梅 | 简单报备 | 内容评估-评估中 | - | - | 2026-04-21 11:04 |
```

> 注意三条数据的「评估单状态」与「中台评估」**各不相同**，严禁复制粘贴同一状态到所有行。

### 3.4 展示规则与 CHECKPOINT

🛑 **输出前自检（缺一不可）：**

1. ✅ 表头恰好 7 列，与 3.1 标准模板一字不差
2. ✅ 每一行「评估单 ID」都渲染为 `[ID](https://szgate.szabot.internal/x/r/doto9awl4o?applyId=ID)` 格式的超链接
3. ✅ 每一行「评估单状态」「中台评估」是**独立两列**，按该条数据自己的 `items` 拼接，不复用别的行
4. ✅ 单元格内多项状态用 `<br>` 竖向堆叠，无「、」「,」「/」等横向分隔符
5. ✅ 未使用 `ridState` 字段

任一条不满足，**必须重新生成表格**，禁止输出给用户。

**其他展示要求：**
- 列表为空时提示"该项目暂无评估单"并引导用户创建
- 列表不为空时以表格形式展示，并提示用户可进行的后续操作（查看详情、创建新评估单等）

展示列表后，提示用户可进行的操作：

```
您可以：

2. 创建一个新的评估单
3. 修改已有评估单
```
