> 🚫 **严格使用限制**：本工作流**仅适用于"修改/更新正式影库项目"场景**。当且仅当用户明确表达了修改已提交正式项目的意图时，才可加载并执行本文件。任何其他场景（创建草稿、修改草稿、删除草稿、查看草稿、普通问答、代码编写、文件操作、信息查询等）**严禁加载或引用本文件**。

## 概述

本工作流**仅适用于更新已提交的正式影库项目**（非草稿），具体流程为：
- 识别用户修改正式项目的意图
- 定位用户要修改的目标项目
- 基于 Schema 识别要修改的字段和新值
- 调用 MCP 工具 `updateProjectPartially` 提交部分更新
- 反馈用户更新结果

### ⚠️ 允许修改的字段白名单

正式项目**仅允许修改以下 24 个字段**，用户请求修改白名单之外的字段时必须拒绝：

## 全局执行规则（执行纪律）

> ⚠️ 以下规则在整个会话期间**始终生效**，不因步骤切换而豁免。

1. **步骤追踪**：每轮回复开头必须以内部注释形式标注当前步骤，格式为：`[当前步骤: Step X — 步骤名称]`
2. **单步执行**：每轮回复只推进一个步骤。完成当前步骤后停止，等待用户输入，**禁止在同一轮回复中执行多个步骤**。例外：Step 1（识别意图）为静默步骤，可与 Step 2 在同一轮执行。
3. **禁止跳步**：即使用户一次性提供了所有信息，也必须按 Step 1 → 2 → 3 → … 顺序逐步确认。
4. **枚举展示约束**：向用户展示枚举选项时，只展示 `label`（中文名称），**禁止展示 `value`（数字/代码值）**。
5. **Schema 忠实约束**：所有字段名、枚举值、类型均以加载的 Schema 文件为唯一事实来源，不得凭记忆猜测或编造字段。
6. **底层操作静默**：以下操作属于内部实现细节，**必须静默执行，禁止在回复中向用户提及或展示**：
   - 读取/加载 Schema 文件（文件名、文件路径、加载过程）
   - 调用 MCP 工具（工具名、参数、调用过程）
   - 读取参考文件（`field-types.md`、`project_update_workflow.md` 等）
   - 解析 Schema 结构（字段属性、behavior 类型、内部分支逻辑）
   - 向用户展示时只呈现**业务层面**的信息（字段名称、选项、验证结果等），不暴露底层技术实现
7. **最小化修改原则**：只处理用户明确要求修改的字段，不主动触碰未提及的字段，不重新验证整个项目。
8. **白名单校验**：在解析用户修改意图时，必须将每个待修改字段与"允许修改的字段白名单"进行比对。白名单外的字段一律拒绝修改，并向用户说明原因。

## Step 1：识别修改意图

确认用户意图为"修改/更新正式项目"而非"修改草稿"。

**意图识别关键词：**
- 修改项目、更新项目、改一下项目、项目改成
- 把项目 XX 的 YY 改成 ZZ
- 更新一下项目 XX 的信息
- 已上线的项目修改

**与「更新草稿」的意图区分：**
- 用户明确提到"项目"（非"草稿"）→ 本工作流
- 用户提到"草稿"或未明确说是项目还是草稿 → 应询问用户确认，或默认走「更新草稿」工作流
- 若用户说"更新项目"但上下文显示在操作草稿 → 应确认是否要更新正式项目

**处理要点：**
- 从用户输入中提取两类信息：**目标项目标识**（项目名称或 ID）和 **修改内容**（要改的字段和新值）
- 若用户未明确指定目标项目，在 Step 2 中引导用户提供
- 本步骤为静默步骤，可与 Step 2 在同一轮执行

## Step 2：定位目标项目

> 本步骤需要确认用户要修改的具体项目，操作过程静默执行（遵守全局规则第 6 条）。
> ⚠️ **必须使用 `szabot_tools.kb_search` MCP 工具检索项目**，不得跳过检索步骤。
> ⚠️ **检索关键词必须使用用户的原始输入**，严禁对用户提供的项目名称做任何处理（如添加空格、拆分、补全书名号、去除标点等）。用户输入什么就原样传入检索接口。

### 2.1 确认项目标识

**情况 A：用户已提供项目名称**
- 使用 `szabot_tools.kb_search` 检索该项目名称
- 检索到唯一结果 → 向用户确认：

```
已找到目标项目：《我的世界》（项目 ID: xxx）
请告诉我您要修改哪些内容？
```

- 检索到多条结果 → 列出候选项请用户选择
- 未检索到结果 → 告知用户未找到，请确认项目名称

**情况 B：用户已提供项目 ID**
- 使用 `szabot_tools.kb_search` 验证该 ID 对应的项目
- 确认存在后向用户展示项目名称进行确认

**情况 C：用户未指定目标项目**
- 请用户提供项目名称或 ID：

```
请提供您要修改的项目名称或项目 ID。
```

### 2.2 确认目标

定位到目标项目后，如果用户在 Step 1 中已同时提供了修改内容，则直接展示确认信息并进入 Step 3，无需重复询问。

---
> 🛑 **CHECKPOINT**: 本步骤完成。确认目标项目后，等待用户提供或确认修改内容，再进入下一步。
> 禁止在同一轮回复中执行多个步骤。

## Step 3：解析修改字段

> ⚠️ **进入本步骤前，必须先读取 `references/field-types.md`，再开始处理任何字段。**
> 同时读取 `references/tv_long_schema.json` 作为字段定义的事实来源。

### 3.1 从用户输入中提取修改意图

解析用户描述，识别出要修改的字段和目标值。每个修改项需要确定：
- **目标字段**：将用户提到的中文名称/label 映射到 Schema 中的**英文 `name`**（如"制作集数"→ `seriesNumber`）。⚠️ **后续调用 MCP 接口时必须使用英文 `name`，严禁使用中文 label**
- **新值**：用户期望修改成的值

> ⚠️ **白名单校验**：提取出所有待修改字段后，**必须逐一比对白名单**（`pname`、`pstatus`、`isCostumeDrama`、`playlet`、`dramaLocation`、`mediaPlatform`、`companyProducer`、`studio`、`producerKpiList`、`marketPMs`、`chiefEditors`、`topicTypeDesc`、`onelineIntro`、`brief`、`sparkle`、`leadRole`、`roleRelations`、`director`、`writer`、`leadActor`、`otherActor`、`leadActorRemark`、`seriesNumber`、`duration`）。
> - 白名单内的字段 → 继续处理
> - 白名单外的字段 → 立即拒绝，告知用户"该字段不支持通过本工具修改，请在影库系统中直接操作"
> - 若用户请求中**全部字段都不在白名单内**，则直接告知用户并终止流程，不进入后续步骤

**示例：**

| 用户输入 | 目标字段 | 新值 | 是否允许 |
|---------|---------|------|---------|
| "项目名改成《新世界》" | `pname` | 新世界 | ✅ 白名单内 |
| "集数从24改成30" | `seriesNumber` | 30 | ✅ 白名单内 |
| "项目简介改成XXX" | `brief` | XXX | ✅ 白名单内 |
| "制片人改成张三" | `producerKpiList` | 张三 | ✅ 白名单内 |
| "导演改成李四" | `director` | 李四 | ✅ 白名单内 |
| "题材类型改成爱-古代爱情" | `topicType2` | 爱,古代爱情-落地古偶 | ❌ 白名单外，拒绝 |
| "合作模式改成版权剧" | `cooperationMode` | 版权剧 | ❌ 白名单外，拒绝 |
| "备案状态改成已送总局" | `dramaBeianStatus` | 已送总局审查 | ❌ 白名单外，拒绝 |

### 3.2 按字段类型处理新值

对每个待修改字段，按 schema 中的 `type` + `behavior` 确定处理方式（与创建工作流一致）：

```
behavior: enum     → 枚举匹配：新值必须匹配 enum_values 中的某个 label
behavior: cascade  → 级联枚举匹配：按层级匹配
behavior: external → 外部查询：用新值作为关键词调用 MCP 工具查询
无 behavior        → 普通字段：按 type 直接赋值，有 format 则校验格式
```

**处理规则参考 `field-types.md` 中对应章节。**

### 3.3 条件字段联动

当前白名单中存在以下需要特殊处理的联动关系：

**`isCostumeDrama`（是否古装）— cascade 级联选择：**
- 该字段为 cascade 类型，第一层选"是/否"，第二层选具体朝代/时代
- 输出使用 `serialization: "csv"` 拼接，如 `"是,隋唐"` 或 `"否,当代（改革开放至今）"`

**`producerKpiList`（制片人）— 条件不可编辑：**
- `managementStatus`（经营状态）不是 Schema 中定义的字段，而是来自 `kb_search` 检索接口的返回结果。在 Step 2 定位项目时需从检索结果中提取并缓存该值。
- 当项目的 `managementStatus` ∈ `已通过开机决策`、`已完成上线前看片`、`已完成粗剪看片`、`已上线`、`已播完` 时，`producerKpiList` **不可编辑**
- 若用户尝试在上述状态下修改制片人，应拒绝并告知："当前项目经营状态为「{managementStatus}」，制片人字段已锁定，不支持修改。如需调整，请在影库系统中直接操作"
- 其他经营状态下，`producerKpiList` 正常可编辑

**其他白名单字段均为独立字段，无条件依赖关系。**

| 字段 | 原值 | 新值 |
|------|------|------|
| 项目简介 | （原简介） | （新简介） |
| 制作集数 | 24 | 30 |
| 单集正片总分钟数 | 45 | 50 |

确认修改请回复"确认"，如需调整请直接说明。

- [ ] **条件不可编辑校验**：若修改 `producerKpiList`，需检查 `managementStatus` 是否 ∈ {已通过开机决策, 已完成上线前看片, 已完成粗剪看片, 已上线, 已播完}，若是则拒绝修改
- [ ] 所有待修改字段的新值类型与 Schema 定义一致
- [ ] 枚举字段的新值在合法 `enum_values` 范围内
- [ ] 外部数据字段：唯一命中项已就绪，多结果和无结果项已收集
- [ ] 数字类型字段为合法数值
- [ ] **Schema 类型校验**：每个字段的实际类型与 Schema 定义一致（`type: string` 不是数组，`type: array` 不是字符串）

### 3.7 用户回复后处理

## Step 4：调用 MCP 更新项目

> 本步骤全程静默执行（遵守全局规则第 6 条），不向用户展示工具名、参数或调用过程。

### 4.1 提交前校验

**参数自检：**

- [ ] `project_id` 为数字类型（如 `12345`），非字符串（如 `"12345"`）
- [ ] `update_fields` 内所有 key 为英文字段名（Schema `name`），非中文 `label`
- [ ] 所有字段均在允许修改的白名单内
- [ ] `type: number` 枚举字段值为数字（非字符串）
- [ ] 其余通用检查项，逐项对照 `references/mcp_param_rules.md` 第 4 节确认

### 4.2 组装更新参数

将确认后的修改字段组装为 `updateProjectPartially` 的调用参数。

**参数格式**：

```json
{
  "project_id": <项目ID>,
  "update_fields": {
    "<field_name_1>": "<new_value_1>",
    "<field_name_2>": "<new_value_2>"
  }
}
```

**参数说明：**
- `project_id`（必填）：目标项目的 ID（**数字类型，非字符串**），来自 Step 2 检索到的项目 ID
- `update_fields`（必填）：一个对象，包含要修改的字段键值对

**`update_fields` 内部的要点：**
- ⚠️ **必须使用英文字段名（Schema 中的 `name`）作为 key**，严禁使用中文名称（`label`）。例如使用 `pname` 而非"项目名称"，使用 `seriesNumber` 而非"制作集数"
- 直接以英文字段名为 key、新值为 value
- 只包含需要修改的字段，不传递未修改的字段
- 字段值的序列化规则与创建工作流一致（如 `serialization: semicolon` 的字段用分号拼接）

**示例**（将项目名改为"新世界"，制作集数改为30）：

```json
{
  "project_id": 12345,
  "update_fields": {
    "pname": "新世界",
    "seriesNumber": 30
  }
}
```

**如调用失败并返回类型错误，必须：**
1. 分析错误信息，定位问题字段
2. 对照 Schema 检查该字段的 `type` 定义
3. 修正格式后重新提交
