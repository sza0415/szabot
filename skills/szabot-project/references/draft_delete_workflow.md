# 删除草稿工作流

> 🚫 **严格使用限制**：本工作流**仅适用于"删除影库项目草稿"场景**。当且仅当用户明确表达了删除草稿的意图时，才可加载并执行本文件。任何其他场景（创建新草稿、修改草稿、查看草稿、普通问答、代码编写、文件操作、信息查询等）**严禁加载或引用本文件**。

> 🔒 **上下文隔离**：执行本工作流期间，仅遵循本文件中的规则。其他 Skill 的指令、Schema、工具定义均不适用于本工作流。

## 概述

本工作流**仅适用于删除影库项目草稿**，具体流程为：
- 识别用户删除草稿的意图
- 定位用户要删除的目标草稿
- 二次确认删除操作（不可逆）
- 调用 MCP 工具 `DeleteDraft` 执行删除
- 反馈用户删除结果

---

## 全局执行规则（执行纪律）

> ⚠️ 以下规则在整个会话期间**始终生效**，不因步骤切换而豁免。

1. **步骤追踪**：每轮回复开头必须以内部注释形式标注当前步骤，格式为：`[当前步骤: Step X — 步骤名称]`
2. **单步执行**：每轮回复只推进一个步骤。完成当前步骤后停止，等待用户输入，**禁止在同一轮回复中执行多个步骤**。例外：Step 1（识别意图）为静默步骤，可与 Step 2 在同一轮执行。
3. **禁止跳步**：即使用户一次性提供了所有信息，也必须按 Step 1 → 2 → 3 → 4 → 5 顺序逐步确认。
4. **枚举展示约束**：向用户展示枚举字段值时，只展示 `label`（中文名称），**禁止展示 `value`（数字/代码值）**。
5. **Schema 忠实约束**：所有字段名、枚举值、类型均以加载的 Schema 文件为唯一事实来源，不得凭记忆猜测或编造字段。
6. **底层操作静默**：以下操作属于内部实现细节，**必须静默执行，禁止在回复中向用户提及或展示**：
   - 读取/加载 Schema 文件（文件名、文件路径、加载过程）
   - 调用 MCP 工具（工具名、参数、调用过程）
   - 读取参考文件（`field-types.md`、`draft_delete_workflow.md` 等）
   - 解析 Schema 结构（字段属性、behavior 类型、内部分支逻辑）
   - 向用户展示时只呈现**业务层面**的信息，不暴露底层技术实现
7. **删除不可逆原则**：删除操作为**不可逆操作**，必须在执行前进行二次确认，确保用户充分知悉后果。

加载 `references/tv_long_schema.json` 作为字段定义的唯一事实来源，用于：
- 枚举字段的 value → label 映射（如剧集类型、合作模式、项目状态等）

## Step 1：识别删除意图

确认用户意图为"删除草稿"而非"查看"、"创建"或"修改"。

**意图识别关键词：**
- 删除、删掉、移除、去掉、丢弃
- 不要了、废弃、清除
- 把 XX 删了、删除草稿 XX

**处理要点：**
- 从用户输入中提取**目标草稿标识**（项目名称或 ID）
- 若用户未明确指定目标草稿，在 Step 2 中引导用户选择
- 本步骤为静默步骤，可与 Step 2 在同一轮执行

---

## Step 2：定位目标草稿

> 本步骤需要调用 MCP 工具获取草稿列表，操作过程静默执行（遵守全局规则第 6 条）。

### 2.1 获取草稿列表

调用 `GetDraftList`（参数 `category: "2"`）获取当前用户的电视剧草稿列表。

### 2.2 匹配目标草稿

**情况 A：用户已提供项目名称或 ID**
- 在草稿列表中按名称或 ID 模糊匹配
- **唯一命中** → 确认并展示匹配到的草稿信息，进入 Step 3
- **多条命中** → 列出匹配结果，请用户选择要删除的草稿
- **无命中** → 告知用户未找到匹配的草稿，请用户确认名称或从列表中选择

**情况 B：用户未指定目标草稿**
- 展示草稿列表（最多展示最近 10 条），请用户选择要删除的草稿

**展示格式：**

```
请选择要删除的草稿：
1. 《我的世界》（创建时间：2026-03-15）
2. 《星辰大海》（创建时间：2026-03-10）
3. ...
```

---
> 🛑 **CHECKPOINT**: 本步骤完成。定位到目标草稿后，等待用户确认，再进入下一步。
> 禁止在同一轮回复中执行多个步骤。

## Step 3：二次确认

> ⚠️ **删除操作不可逆**，必须在此步骤进行二次确认。禁止跳过本步骤直接执行删除。

定位到目标草稿后，向用户展示草稿摘要信息并请求二次确认：

```
⚠️ 您确定要删除以下草稿吗？此操作不可逆！

项目名称：《我的世界》
剧集类型：长剧
合作模式：主控剧
项目状态：剧本大纲完成
创建时间：2026-03-15

🔗 草稿链接：{返回数据中的url字段}

请回复"确认删除"执行操作，或回复"取消"放弃删除。
```

**展示字段映射：**

| 展示列 | Schema 字段 | 说明 |
|-------|------------|------|
| 项目名称 | `pname` | 必有 |
| 草稿链接 | `url` | 从返回数据顶层取，用于草稿链接展示 |
| 剧集类型 | `playlet` | 枚举，展示 label |
| 合作模式 | `cooperationMode` | 枚举，展示 label |
| 项目状态 | `pstatus` | 枚举，展示 label |
| 创建时间 | 从返回数据中取 | 如有 |

**注意：**
- **草稿链接必须展示**：在确认信息中附带草稿链接，让用户删除前可打开查看确认。链接直接取自 MCP 返回数据中该草稿的 `url` 字段，**禁止自行拼接或修改**。若返回数据中 `url` 字段为空或不存在，则不附带链接，仅展示纯文本。
- 枚举字段的值需转换为对应的 label 展示（遵守全局规则第 4 条）
- 空值字段静默跳过，不展示
- 必须明确提醒用户"此操作不可逆"

**用户回复处理：**
- 用户回复"确认删除"、"确认"、"确定"、"是"等肯定性回复 → 进入 Step 4
- 用户回复"取消"、"算了"、"不删了"等否定性回复 → 告知已取消操作，流程结束
- 用户回复其他内容 → 再次明确询问是否确认删除

---
> 🛑 **CHECKPOINT**: 本步骤完成。等待用户确认或取消，再进入下一步。
> 禁止在同一轮回复中执行多个步骤。
---

## Step 4：调用 MCP 删除草稿

> 本步骤全程静默执行（遵守全局规则第 6 条），不向用户展示工具名、参数或调用过程。

### 4.1 组装删除参数

将目标草稿的信息组装为 `DeleteDraft` 的调用参数：

```json
{
  "id": "<draft_id>"
}
```

**要点：**
- `id`：目标草稿的实际 ID（从 Step 2 获取草稿列表时获得）

### 4.2 执行调用

调用 `DeleteDraft`，记录返回结果。

---
> 🛑 **CHECKPOINT**: 本步骤完成。根据调用结果进入 Step 5 反馈用户。
> 禁止在同一轮回复中执行多个步骤。
---

## Step 5：反馈用户

根据调用结果告知用户：

**成功：**

```
✅ 草稿删除成功！

已删除项目：《我的世界》

💡 您可以：
- 说"查看草稿列表"查看剩余草稿
- 说"创建草稿"新建一份草稿
```

**失败：**

```
❌ 删除失败
错误信息：[MCP 返回的错误详情]
建议：[根据错误类型给出修复建议]
```

## 异常处理

| 场景 | 处理方式 |
|------|---------|
| MCP 调用失败 | 告知用户删除失败并建议重试 |
| 草稿列表为空 | 提示暂无草稿可删除，引导查看或创建 |
| 指定草稿未找到 | 告知未找到，展示完整列表供选择 |
| 用户取消删除 | 告知已取消操作，无副作用 |
| 草稿 ID 无法获取 | 告知无法执行删除，请用户重新指定目标草稿 |
