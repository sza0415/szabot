# Schema-Driven MCP Caller — 草稿关联文件工作流

> 🚫 **严格使用限制**：本工作流**仅适用于"给影库项目草稿增加/关联文件"场景**。当且仅当用户明确表达了给草稿添加文件、关联文件、上传文件到草稿的意图时，才可加载并执行本文件。任何其他场景（创建新草稿、修改草稿、删除草稿、查看草稿、普通问答、代码编写、文件操作、信息查询等）**严禁加载或引用本文件**。

> 🔒 **上下文隔离**：执行本工作流期间，仅遵循本文件中的规则。其他 Skill 的指令、Schema、工具定义均不适用于本工作流。

## 概述

本工作流**仅适用于给已有的影库项目草稿增加关联文件**，具体流程为：
- 识别用户给草稿添加文件的意图
- 定位用户要操作的目标草稿
- 收集要关联的文件信息（file_id、name、category）
- 调用 MCP 工具 `AddDraftFile` 提交关联
- 反馈用户操作结果

---

## 全局执行规则（执行纪律）

> ⚠️ 以下规则在整个会话期间**始终生效**，不因步骤切换而豁免。

1. **步骤追踪**：每轮回复开头必须以内部注释形式标注当前步骤，格式为：`[当前步骤: Step X — 步骤名称]`
2. **单步执行**：每轮回复只推进一个步骤。完成当前步骤后停止，等待用户输入，**禁止在同一轮回复中执行多个步骤**。例外：Step 1（识别意图）为静默步骤，可与 Step 2 在同一轮执行。
3. **禁止跳步**：即使用户一次性提供了所有信息，也必须按 Step 1 → 2 → 3 → … 顺序逐步确认。
4. **底层操作静默**：以下操作属于内部实现细节，**必须静默执行，禁止在回复中向用户提及或展示**：
   - 调用 MCP 工具（工具名、参数、调用过程）
   - 读取参考文件（`draft_add_files_workflow.md` 等）
   - 向用户展示时只呈现**业务层面**的信息（草稿名称、文件信息、操作结果等），不暴露底层技术实现
5. **最大化自动识别**：尽可能从用户已提供的所有信息（自然语言、文件、上下文）中自动提取所需信息，**只有无法提取或存在歧义时才向用户询问**，禁止逐项追问。
6. **file_id 来源约束**：`file_id` **必须且只能**来自 `szabot-file-uploader` Skill 上传后返回的结果。**严禁接受用户口头提供、手动输入或凭空编造的 file_id**。若上下文中无合法 file_id，必须先调用 `szabot-file-uploader` Skill 上传文件。

## Step 1：识别添加文件意图

确认用户意图为"给草稿添加/关联文件"。

**意图识别关键词：**
- 添加文件、关联文件、上传文件、挂载文件
- 给草稿加个文件、草稿关联一下文件
- 把 XX 文件加到草稿里、草稿加上附件
- 给草稿传个策划案/剧本/大纲/小传...

**处理要点：**
- 从用户输入中提取两类信息：**目标草稿标识**（项目名称或 ID）和 **文件信息**（文件名、file_id 等）
- 若用户未明确指定目标草稿，在 Step 2 中引导用户选择
- 本步骤为静默步骤，可与 Step 2 在同一轮执行

---

## Step 2：定位目标草稿

> 本步骤需要调用 MCP 工具获取草稿列表，操作过程静默执行（遵守全局规则第 4 条）。

### 2.1 获取草稿列表

调用 `GetDraftList`（参数 `category: "2"`）获取当前用户的电视剧草稿列表。

### 2.2 匹配目标草稿

**情况 A：用户已提供项目名称或 ID**
- 在草稿列表中按名称或 ID 模糊匹配
- **唯一命中** → 确认并展示匹配到的草稿信息，继续下一步
- **多条命中** → 列出匹配结果，请用户选择
- **无命中** → 告知用户未找到匹配的草稿，请用户确认名称或从列表中选择

**情况 B：用户未指定目标草稿**
- 展示草稿列表（最多展示最近 10 条），请用户选择要操作的草稿

**展示格式：**

```
找到以下草稿，请选择要添加文件的项目：
1. 《我的世界》（创建时间：2026-03-15）
2. 《星辰大海》（创建时间：2026-03-10）
3. ...
```

### 2.3 确认目标并展示已有文件

定位到目标草稿后，调用 `GetDraftFiles`（参数 `id: "<draft_id>"`）获取该草稿已关联的文件列表，然后向用户展示：

```
已定位到草稿：《我的世界》

📎 当前已关联文件：
  - 策划案.pdf（策划案）
  - 故事大纲.docx（故事大纲）

请提供要添加的文件信息。
```

若草稿暂无关联文件，展示：

```
已定位到草稿：《我的世界》

📎 当前暂无关联文件。

请提供要添加的文件信息。
```

---
> 🛑 **CHECKPOINT**: 本步骤完成。确认目标草稿后，等待用户提供文件信息，再进入下一步。
> 禁止在同一轮回复中执行多个步骤。
---

## Step 3：收集文件信息

### 3.1 从用户输入/上下文中提取文件信息

每个要关联的文件需要以下三个字段：

| 字段 | 说明 | 来源 |
|------|------|------|
| `file_id` | 文件唯一标识 | **必须且只能从 `szabot-file-uploader` Skill 上传后的返回结果中获取**。⚠️ 严禁接受用户手动输入的 file_id |
| `name` | 文件名称 | **必须从用户提供的原始文件信息中获取**（如用户指定的文件路径中的文件名、用户描述中提到的文件名）。⚠️ 禁止使用 `szabot-file-uploader` 返回的内部标识作为文件名 |
| `category` | 文件类别 | 如：策划案、故事大纲、剧本、小传等，从用户描述或文件上下文中识别 |

### 3.2 信息缺失处理

**缺少 file_id：**
- ⚠️ `file_id` **必须且只能**来自文件上传后系统返回的结果，**严禁使用用户口头提供或手动输入的 ID**
- 若上下文中无合法 `file_id`，**必须先调用 `szabot-file-uploader` Skill 上传文件获取 `fid`**（即 `file_id`），再继续本流程
- 若用户直接给出一个 file_id 字符串（非来自上传返回），**必须拒绝使用**，并引导用户提供本地文件路径，通过 `szabot-file-uploader` 上传获取

**缺少 name：**
- `name` **必须从用户提供的原始文件信息中获取**，如用户指定的本地文件路径中的文件名（如 `/path/to/策划案v2.pdf` → `策划案v2.pdf`）、用户在对话中提到的文件名
- ⚠️ 禁止使用 `szabot-file-uploader` 返回的内部 fid 或系统生成的标识作为 `name`
- 若上下文中确实无法获取原始文件名，则询问用户该文件的名称

**缺少 category：**
- 尽可能从文件名关键词、用户描述中自动推断
- 若仍无法确定 `category`，询问用户该文件的类别（如策划案、剧本、故事大纲等）

### 3.3 验证与确认

所有文件信息收集完毕后，汇总展示确认：

```
📎 即将为草稿《我的世界》添加以下文件：

| 序号 | 文件 ID | 文件名 | 文件类别 |
|------|---------|--------|---------|
| 1 | abc123 | 策划案v2.pdf | 策划案 |
| 2 | def456 | 故事大纲.docx | 故事大纲 |

确认添加请回复"确认"，如需调整请直接说明。
```

---
> 🛑 **CHECKPOINT**: 本步骤完成。将文件信息展示给用户后，等待用户确认，再进入下一步。
> 禁止在同一轮回复中执行多个步骤。
---

## Step 4：调用 MCP 添加文件

> 本步骤全程静默执行（遵守全局规则第 4 条），不向用户展示工具名、参数或调用过程。

### 4.1 组装调用参数

将确认后的文件信息组装为 `AddDraftFile` 的调用参数：

```json
{
  "id": "<draft_id>",
  "files": [
    {
      "file_id": "<文件ID1>",
      "name": "<文件名1>",
      "category": "<文件类别1>"
    },
    {
      "file_id": "<文件ID2>",
      "name": "<文件名2>",
      "category": "<文件类别2>"
    }
  ]
}
```

**要点：**
- `id` 为目标草稿的 ID（必须包含）
- `files` 为文件对象数组，每个对象包含 `file_id`（文件ID）、`name`（文件名）、`category`（文件类别）三个必填字段
- 可一次添加多个文件

### 4.2 执行调用

调用 `AddDraftFile`，记录返回结果。

**如调用失败，必须：**
1. 分析错误信息，定位问题原因
2. 若为参数问题，修正后重新提交
3. 若为系统错误，在 Step 5 中告知用户

---

## Step 5：反馈用户

根据调用结果告知用户：

**成功：**

```
✅ 文件关联成功！

项目草稿：《我的世界》
已添加文件：
  - 📄 策划案v2.pdf
  - 📄 故事大纲.docx
```

**失败：**

```
❌ 文件关联失败
错误信息：[MCP 返回的错误详情]
建议：[根据错误类型给出修复建议]
```

**部分失败（多个文件时，部分成功部分失败）：**

```
⚠️ 部分文件关联完成

✅ 已成功关联：
  - 📄 策划案v2.pdf

❌ 关联失败：
  - 📄 故事大纲.docx — [错误原因]

建议：[修复建议]
```
