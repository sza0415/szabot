# 数据来源判定与前置处理工作流

> 🚫 **严格使用限制**：本工作流**仅作为前置处理步骤**，在进入下游业务工作流**之前**执行。用于判定用户数据来源并完成前置数据准备，不涉及草稿/项目的创建或修改本身。

> 🔒 **上下文隔离**：本工作流仅负责"数据从哪来、怎么准备"，不处理"数据怎么用"。数据准备完成后，将结果传递给下游工作流。

## 概述

创建草稿、更新草稿和更新项目都需要从用户处获取影视信息。信息来源有两种：

1. **文本输入**：用户通过自然语言直接描述影视信息
2. **文件输入**：用户提供本地文件（策划书、立项书、PPT、表格、PDF 等），需先上传解析后提取信息

本工作流负责判断来源类型，并在文件输入场景下，按需调用前置技能完成数据准备。

---

## 全局执行规则

1. **本工作流必须在下游工作流之前执行**：先完成数据来源判定和准备，再进入具体的创建/更新流程
2. **智能跳步**：根据上下文已有信息，从最早的缺失步骤开始执行，跳过已完成的步骤
3. **失败即终止**：前置步骤失败时，告知用户具体错误并终止流程，不进入下游工作流
4. **结果透传**：将准备好的数据（文本内容 + 可选的 fid/文件名信息）完整传递给下游工作流

---

## Step 1：判断数据来源

根据以下规则判断用户的数据来源类型：

### 判定为「文件输入」的条件（满足任一即可）

- 用户消息中包含本地文件路径（如 `/path/to/file.pdf`、`~/Documents/策划书.docx`）
- 用户明确提及"从文件中提取""根据这个文件""解析这个文件"
- 用户说"根据这个策划书创建""用这个立项书更新"
- 对话上下文中已有 `fid`（如用户此前已用 `szabot-file-uploader` 上传过）但尚无解析文本
- 对话上下文中已有文件解析文本（如用户此前已用 `szabot-file-parser` 解析过）

### 判定为「文本输入」的条件

- 用户直接输入影视信息文本（如项目名称、演员、集数等描述性内容）
- 无文件路径、无 fid、无文件解析文本

### 无法判定时

询问用户：

```
请问您是要直接输入项目信息，还是从文件中提取？
- A. 直接输入（我来描述项目信息）
- B. 从文件提取（我有策划书/立项书等文件）
```

---

## Step 2：按来源类型准备数据

### 路径 A：文本输入

无需前置处理。直接将用户文本作为输入，进入下游工作流。

**输出**：用户原始文本 → 传递给下游工作流的字段提取步骤

### 路径 B：文件输入

#### Step B.0：文件类型判定（必须首先执行）

根据文件扩展名判定处理方式，分为两条子路径：

| 文件扩展名 | 子路径 | 处理方式 |
|-----------|--------|---------|
| `doc`、`docx`、`ppt`、`pptx`、`pdf` | **路径 B-I**（szabot-file-parser） | 上传 + 远程解析，由 `szabot-file-parser` 技能处理 |
| `xls`、`xlsx`、`csv` | **路径 B-II**（本地 Excel 读取） | 本地安装 Python 库，直接读取全部数据 |

> ⚠️ 如果文件扩展名不属于以上任何类型，告知用户当前仅支持 Word（doc/docx）、PPT（ppt/pptx）、PDF、Excel（xls/xlsx）和 CSV 文件，请用户转换格式后重试。

---

#### 路径 B-I：Word / PPT / PDF 文件（szabot-file-parser）

适用扩展名：`doc`、`docx`、`ppt`、`pptx`、`pdf`

完整链路为：

```
Step B-I.1: szabot-file-uploader  →  上传文件，获得 fid
Step B-I.2: szabot-file-parser    →  传入 fid，解析文件，获得结构化文本
```

**关键：根据上下文已有信息，智能跳步。**

| 上下文已有信息 | 起始步骤 | 说明 |
|---|---|---|
| 用户提供本地文件路径，无 fid | Step B-I.1 | 完整链路：上传 → 解析 |
| 已有 `fid`（如用户已用 `szabot-file-uploader` 上传过），无解析文本 | Step B-I.2 | 跳过上传，直接解析 |
| 已有文件解析文本（如用户已用 `szabot-file-parser` 解析过） | 跳过全部 | 直接使用已有文本，进入下游工作流 |

##### Step B-I.1：上传文件（需要时）

调用 **`szabot-file-uploader`** 技能上传用户的本地文件。

**执行要点：**
- 传入用户文件的绝对路径
- 成功后获得 `fid`（文件唯一标识，**来自 `szabot-file-uploader` 返回结果**）和文件元信息
- **文件名必须从用户提供的原始文件信息中获取**（如用户指定的本地文件路径中的文件名），⚠️ 禁止使用 `szabot-file-uploader` 返回的内部标识作为文件名
- 将 `fid`（来自 `szabot-file-uploader` 返回）和文件名（来自用户原始文件信息）保存在上下文中，供后续步骤使用
- 失败时告知用户具体错误，终止流程

##### Step B-I.2：解析文件（需要时）

调用 **`szabot-file-parser`** 技能解析文件内容。

**执行要点：**
- 传入 `fid`，创建解析任务
- 解析通常需要 1~3 分钟，耐心等待轮询结果
- 成功后获得文件的结构化文本内容
- 将解析文本保存在上下文中，供下游工作流使用
- 失败时告知用户具体错误，终止流程

**输出**：解析文本 + fid + 文件名 → 传递给下游工作流

---

#### 路径 B-II：Excel / CSV 文件（本地读取）

适用扩展名：`xls`、`xlsx`、`csv`

> ⚠️ `szabot-file-parser` **不支持** Excel/CSV 类型文件，必须使用本地 Python 库直接读取。

完整链路为：

```
Step B-II.1 & B-II.2: 运行 scripts/read_excel.py 读取文件全部数据（自动安装依赖）
Step B-II.3: 上传原始文件获得 fid（可选，仅在下游需要 fid 时执行）
```

##### Step B-II.1 & B-II.2：读取文件全部数据

使用技能包内置脚本 `scripts/read_excel.py` 读取文件的**全部 sheet、全部行列数据**。

**脚本位置**：`scripts/read_excel.py`（位于本技能包 `szabot-project` 目录下）

**执行方式：**

```bash
python scripts/read_excel.py <文件绝对路径>
```

**脚本说明：**
- 脚本会**自动检测并安装**缺失的依赖库（`pandas`、`openpyxl`、`xlrd`），无需手动安装
- 根据文件扩展名自动选择读取方式：
  - `.csv` → 自动尝试多种编码（UTF-8、GBK、GB2312、Latin1）
  - `.xls` / `.xlsx` → 读取全部 sheet，每个 sheet 标注名称
- **输出全部数据到 stdout**，不截断、不采样
- 错误信息输出到 stderr

**执行要点：**
- 捕获 stdout 作为读取的全部文本内容
- 如果脚本返回非零退出码，将 stderr 中的错误信息告知用户，终止流程

##### Step B-II.3：上传原始文件获得 fid（可选）

如果下游工作流需要将文件关联到草稿/项目（如 `draft_add_files_workflow` 或 `project_add_files_workflow`），还需调用 **`szabot-file-uploader`** 技能上传原始 Excel/CSV 文件获得 `fid`。

- 仅在下游明确需要 fid 时执行
- 执行要点同路径 B-I 的 Step B-I.1

**输出**：读取的全部文本内容 + 文件名 + fid（可选） → 传递给下游工作流

---

## Step 3：输出数据，交回调用方

| 数据来源 | 输出内容 |
|---------|---------|
| 文本输入 | 用户原始文本 |
| 文件输入（Word/PPT/PDF） | 解析文本 + fid + 文件名 |
| 文件输入（Excel/CSV） | 读取的全部文本内容 + 文件名 + fid（可选） |
