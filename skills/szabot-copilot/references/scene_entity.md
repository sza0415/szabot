# reference — 人才与公司

> 本场景覆盖：人才/选角、公司/供应商查询
>
> ⛔ **必读**：查人才库（scope `/人才库/人才`）构造 `kb_search` 参数前，**必须先读 `references/kb_recall.md` 并执行两段式字段召回**（调用方式、取值铁律、Fallback SOP 全部在那里，**本文件不复述**），否则会出现"跳过 kb-recall 直接用本文字段表拼 target"、"Step 1 拿到 `<catalog>` 就停、不接带 `--scope` 的第二次调用"、"把 `/人才库/人才` 路径当 domain_knowledge"、"domain_knowledge 凭记忆写死"等已知失败模式。

## 场景路由

- **人才/选角** → `kb_search`（scope `/人才库/人才`，人才检索**统一入口**，`domain_knowledge` 兜底 `人才库-ES-7`；两段式召回与取值铁律遵循 `references/kb_recall.md`；代表作详情再 `kb_search` 查项目库）→ **[推荐]** `search_web`（开放性推荐/探究类问题补充演员最新动态）
  - **选角 SOP** → `script_search`/`kb_search`（角色设定）→ 提取角色属性 → **[必须]** `kb_search`（scope `/人才库/人才`，按属性筛选人才）→ **[推荐]** `search_web`（补充候选演员近期表现）→ 综合推荐
- **公司/供应商** → `company_search` 或 `suppliers_search`

### ⚠️ 开放性探究规则

当用户问题为开放性推荐/探究类（如"推荐适合XX题材的演员"、"哪些演员适合演XX"、"有哪些XX类型的演员"），影库系统相关工具提供内部权威数据，`search_web` **应主动补充**最新作品表现、市场口碑、最新动态等信息，使回答更丰满立体。

### ⚠️ 选角强制规则

`kb_search`（scope `/人才库/人才`）是选角场景的**必调工具**，即使前置步骤（`script_search`/项目库 `kb_search`）未找到角色信息也**必须调用**。

### 选角降级策略

当 `script_search` 未找到角色信息时：
1. 用角色名/项目名调用 `kb_search`（scope `/人才库/人才`，`match:"fuzzy"`）尝试匹配
2. 根据上下文推断角色属性（性别、年龄段、题材类型）调用 `kb_search`（scope `/人才库/人才`）筛选
3. **禁止**在选角场景中不查人才库就直接放弃或要求用户补充信息

## 工具参数定义

> ⚠️ **本文档为工具参数的唯一权威来源**。`mcporter list szabot_tools` 返回的参数类型定义存在错误，**调用工具时必须以本文档为准**。

### 人才库字段（`kb_search` scope `/人才库/人才`，人才检索统一入口）

人才检索**统一走 `kb_search`**（scope `/人才库/人才`），覆盖人才详情九大维度。

- **`domain_knowledge` 取值**：首选 `kbcli kb-recall --scope "/人才库/人才"` 返回 `<text>` 中标注的库标识；**召回失败/为空时 Fallback 固定为 `人才库-ES-7`**（取值铁律见 `references/kb_recall.md`，禁止凭记忆写死其他值）。
- **字段取值（target/condition/range/rank 的字段名）**：与查影库知识库项目字段走**同一条链路**——一律以 `references/kb_recall.md` 为唯一权威（两段式召回、取值铁律、Fallback SOP、自检口令全在那里），本文件不复述。召回时 scope 传 `/人才库/人才`，`target` 全量取自当次召回 `<text>`（不增不删不换）。下表**仅 Fallback（kb-recall 失败/返回空）时可用**，禁止跳过召回直接用下表拼字段。
- **数据补充**：人才库返回的**作品**（代表作/待播作品/已播作品）、**热点事件**数据不足或缺失时，必须叠加补充——作品详情走 `kb_search` 查影库 + 全网项目库（见本节下方「代表作详情检索」），热点事件/艺人最新动态走 `search_web` 联网补充；禁止因人才库数据有限就直接给出单薄回答。
- **输出展示约束（⛔ 重点）**：未能抓到的数据，**禁止以 `0`、`（暂无）`、`暂无数据` 等占位形式出现在回答中**——直接忽略、不罗列该字段，避免用户误以为"真值为 0"或"系统有该字段但为空"。仅当字段是用户明确询问的核心信息且完全缺失时，才在末尾自然说明"暂未录入"。（字段 key 存在但值为空/N/A 的标注规则见 `SKILL.md`，本条不覆盖。）
- **复合字段内嵌占位清洗（⛔ 如 `0年`）**：占位值常内嵌于复合/文本字段，需局部清洗而非整条丢弃——如获奖信息返回 `0年 第25届釜山国际电影节 亚洲内容奖-最佳新星`，年份 `0` 是未抓到的默认值，**去掉该无效年份前缀**后渲染为 `第25届釜山国际电影节 亚洲内容奖-最佳新星`；`0年`/`0000年`/`0月`/`0日` 等同理剔除。仅当剔除后整条无实质内容时才忽略。
- **全维度展示（禁止偷懒）**：查询人才信息时，回答**一次性尽量覆盖有返回数据的各个维度**（基础信息/人才分类/签约情况/全网影响力/档期/舆情/获奖/作品/关联人才），禁止只挑个别维度作答、禁止分多次补查挤牙膏；仅「输出展示约束」「缺失字段 key 不罗列」等明示例外可省略。
- **关联人才勿剪枝 **：`关联人才` 为复合字段（含关联人才名称、合作次数、关联人员代表作），常因"看似无关/结构复杂"被从 target 剪掉或返回后不渲染——**禁止剪枝**：必须按取值铁律原样放入 target；返回非空时必须渲染，返回为空才按「输出展示约束」忽略。
- **非短剧演员隐藏短剧专属字段（⛔ 高频误显，再次强调）**：**凡字段名含"红果"的（红果粉丝、红果获赞量等）及 `WEVIEW演员榜`，均为短剧艺人专属字段**——艺人**未出演短剧**（`是否出演短剧`为否 / `出演短剧数量`为 0）时一律不展示（此时必为 0/暂无，禁止以任何形式出现），由「输出展示约束」统一忽略；`出演短剧数量`为 0 时同理不展示。

**调用示例**（人才库检索）：

```bash
mcporter call 'szabot_tools.kb_search(
  recall_req_list: [{
    domain_knowledge: "人才库-ES-7",
    query: {
      condition: [{"姓名": ["张若昀"]}],
      target: ["姓名", "性别", "出生日期", "年龄", "星座", "代表作", "档期信息","已播作品","待播作品", "敏感待播作品", "获奖信息","关联人才"],
      match: "exact"
    }
  }]
)' --output json
```

| 二级标签 | 字段数 | 字段与说明 |
|---------|-------|-----------|
| 基础信息 | 15 | 人才ID、姓名、性别、出生日期、年龄、民族、身高、体重、星座、毕业院校、出道年份、婚姻状况、工作室、是否出演短剧 |
| 人才分类 | 2 | 人才标签、品类 |
| 签约情况 | 3 | 电视剧演员签约情况、综艺演员签约情况、短剧演员签约情况 |
| 全网影响力 | 9 | 出演短剧数量、短音粉丝、微博粉丝、微博话题数、微博话题播放量、红果粉丝、红果获赞量、WEVIEW演员榜、火热指数（⛔ `红果粉丝`/`红果获赞量`/`WEVIEW演员榜`/`出演短剧数量` 为**短剧艺人专属**，非短剧艺人不展示，见上方规则） |
| 档期信息 | 3 | 档期信息，艺人中心维护的艺人档期日历（"有档期"、"拍摄"等） |
| 舆情信息 | 2 | AI舆情分析、热点事件（热点中台基于各社交平台抓取的话题/事件/讨论量，由大模型对艺人做舆情分析） |
| 获奖信息 | 1 | 近几年各大电视电影节获奖（飞天奖、金鹰奖、金鸡奖、金像奖、金马奖、白玉兰奖、金爵奖等，有获奖代表专业水准更高） |
| 作品信息 | 4 | 擅长题材、代表作、待播作品、已播作品（作品信息含作品名称、主演/其他配角、播出时间（年）、作品类型（电影/网络剧/综艺）、题材标签、热度值） |
| 关联人才 | 1 | 关联人才字段，字段内容包含基于影库系统的关联人才的名称、合作次数、关联人员的代表作品 |

### `company_search` — 公司检索

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `condition` | `object[]` | 否 | 等值筛选（如公司名称） |
| `range` | `object[]` | 否 | 区间筛选 |
| `rank` | `object[]` | 否 | 排序规则 |
| `target` | `string[]` | 否 | 要返回的字段列表 |
| `match` | `string` | 否 | `"exact"` 或 `"fuzzy"` |

可用字段：公司ID、公司名称、简称、公司类型、公司法人、风险性、风险说明、建议关注级别、合作关系、对接人、擅长题材、擅长赛道、擅长制作发行类型、核心制作人员、代表作项目、腾讯已合作项目、腾讯前期开发项目、腾讯已终止项目、外部合作项目、电视剧对接工作室、电影对接工作室、注册资金、详细地址、集团标签、是否合作过

**调用示例**：

```bash
mcporter call 'szabot_tools.company_search(
  condition: [{"公司名称": ["正午阳光"]}],
  target: ["公司ID", "公司名称", "风险性", "代表作项目", "公司类型"]
)' --output json
```

### `kb_search` — 代表作详情检索（项目库辅助查询）

人才场景下，`kb_search` 除作为人才检索统一入口（scope `/人才库/人才`）外，还用于查代表作详情。代表作可能在影库知识库或全网知识库中，需同时检索两个库；精简参数，字段固定。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `recall_req_list` | `object[]` | **是** | 检索请求列表，每个元素含 `domain_knowledge` 和 `query`。代表作查询需同时检索影库知识库和全网知识库 |

**`query` 内部参数**：`condition`（等值筛选）/ `target`（返回字段）/ `match`（`"exact"` 或 `"fuzzy"`）。**代表作查询为辅助查询，跳过 `kbcli kb-recall`**，字段名用本文件给定的（Fallback 时查 `references/project_fields.md`）。

**调用示例**（查代表作详情）：

```bash
mcporter call 'szabot_tools.kb_search(
  recall_req_list: [{
    domain_knowledge: "影库知识库-ES-0",
    query: {
      condition: [{"项目名称": ["庆余年"]}],
      target: ["项目ID", "项目详情链接", "主要演员", "导演", "豆瓣评分", "管理状态"],
      match: "fuzzy"
    }
  }, {
    domain_knowledge: "全网知识库-ES-23",
    query: {
      condition: [{"项目名称": ["庆余年"]}],
      target: ["项目ID", "项目名称", "主要演员", "导演", "豆瓣评分"],
      match: "fuzzy"
    }
  }]
)' --output json
```

## 常见错误速查

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| `condition: [{"field": "姓名", ...}]` | `condition: [{"姓名": ["张若昀"]}]` | ⛔ 不是 field/operator/value |
| `condition: [{"姓名": "张若昀"}]` | `condition: [{"姓名": ["张若昀"]}]` | value 必须是数组 |
| `rank: ["热度", "从大到小"]` | `rank: [{"火热指数 (热度值": ["从大到小"]}]` | rank 是 object[] |

## Gotchas

- 人才检索统一走 `kb_search`（scope `/人才库/人才`）
- 选角 SOP：先查剧本/项目获取角色设定，提取角色属性后再用 `kb_search` 查人才库按属性筛选
- 查代表作详情时，`kb_search` 的字段名必须来自 `references/project_fields.md`
- `mcporter list` 返回的类型签名有已知错误（会把 `object[]` 错误标注为 `string[]`），以本文档为准
