## 工具参数定义

> ⚠️ **本文档为工具参数的唯一权威来源**。`mcporter list szabot_tools` 返回的参数类型定义存在错误（如将 `object[]` 错误标注为 `string[]`、将必填参数标为可选等）。**调用工具时必须以本文档为准，忽略 `mcporter list` 的签名描述。**
>
> ℹ️ `kbcli kb-recall` 是本地 CLI（不是 MCP 工具，`mcporter list` 不会列出），调用方式见 `references/kb_recall.md`。

### `kb_search` — 项目检索

影库数据库核心工具，支持多知识库并行查询。通过 `recall_req_list` 传入一个或多个检索请求。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `recall_req_list` | `object[]` | **是** | 检索请求列表，每个元素包含 `domain_knowledge` 和 `query` |

**`recall_req_list` 元素结构**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `domain_knowledge` | `string` | 知识库标识字符串，取值遵循 `references/kb_recall.md` 取值铁律（首选 kb-recall 返回值，兜底从 scene reference 文件中取，禁止凭记忆写死） |
| `query` | `object` | 查询参数 |

**`query` 内部参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `condition` | `object[]` | 否 | 等值筛选条件，多个条件之间为 AND 关系。字段名必须来自`kbcli kb-recall` 返回 |
| `range` | `object[]` | 否 | 区间筛选，如播出时间、评分等 |
| `rank` | `object[]` | 否 | 排序规则 |
| `target` | `string[]` | 否 | 要返回的字段列表 |
| `match` | `string` | 否 | `"exact"` 或 `"fuzzy"`，默认精确匹配 |
| `view` | `object` | 否 | 视图查询（用于热度趋势、侵权趋势等） |

#### target / domain_knowledge 取值 → 见 `references/kb_recall.md`

**`domain_knowledge` 与 `target`（及 condition/range/rank 的字段名）的取值方式，一律以 `references/kb_recall.md` 为唯一权威**（两段式召回、取值铁律、Fallback SOP 都在那儿）。本文件**不再复述**，避免"看完这里就以为够了"。

**仅 Fallback 时（kb-recall 失败/返回空）**，按以下 SOP 构造 target：

**① 默认 target（用户未指定字段时的兜底骨架）**：

```
# 标识 / 链接（关联 + 跳转，永远必带）
"项目ID", "项目名称", "项目详情链接",

# 核心画像（基础信息默认骨架）
"项目评级", "合作模式", "开发状态",
"题材赛道", "题材类型",
"制作公司", "导演", "编剧", "主要演员",
"所属工作室", "所属工作室群", "制片人",
"播出时间",

# 项目关键进展（渲染门控见 § 项目进展规范）
"项目关键制作进度", "项目举灯", "项目进展"
```

- **标识 / 链接 3 项**：`项目ID` / `项目名称` / `项目详情链接` 用于数据关联、文案锚点及链接跳转（`项目详情链接` 由 MCP 直接返回 URL，非空即为有效链接）。**这 3 项无论用户是否指定字段都必须带回**
- **核心画像 12 项**：仅当用户**未指定**字段时作为基础信息场景的语义骨架默认铺底；用户已指定字段时按用户的来
- **项目关键进展 3 项**：仅当用户**未指定**字段时默认带回，用于渲染「📍 项目关键进展」板块（渲染门控见 § 项目进展规范，不影响字段是否取回）

**② 宽取原则（反贪省，仅 Fallback 时生效）** — 除非用户**明确列出**要哪些字段，否则禁止只返回少量字段。必须打开 `project_fields.md` 做语义扫描，把所有**语义相关**或**关键词匹配**的字段名全部放进 target。

**③ 构造 target 的 Fallback SOP（打开 `project_fields.md` 后逐条执行）**
1. **提取用户问题中的语义关键词**（通常是名词 / 类目词）
2. **在 `project_fields.md` 中做关键词匹配**，凡满足以下任一条件的字段都要加入 target：
   - 字段名直接包含关键词
   - 字段的"说明"栏包含关键词或其近义词
   - 字段的"说明"栏出现「简称：xxx」「别名：xxx」且 xxx 命中关键词 —— 必须把简称/别名**翻译回正式字段名**再放进 target
   - 字段属于同一业务语义组
3. **不要自己判断字段"是否会有数据"来决定是否取回**
4. **target 体量参考**：宁可 15~25 个字段一次取回，也不要 5~8 个字段来回查 3 次
5. **查完再筛选**：拿到结果后再在回答里重点展示

**⚠️ 再次强调**：以上 ①②③ **仅在 Fallback 时执行**。kb-recall 成功后，target 只能是 kb-recall 返回的全部字段，禁止用默认列表或语义扫描结果替换/补充。

**常见反例（禁止出现）**：
- ❌ kb-recall 返回了 11 个字段，却传入 18 字段默认集（忽略了 kb-recall 结果）
- ❌ kb-recall 返回了 40 个字段，只选了 19 个传入（自行筛选删减）
- ❌ 凭想象往 target 塞根本不存在的字段名（如 `"已签约嘉宾"`、`"节目嘉宾"` 都不是合法字段）

#### view 参数详细格式

```
view: {
  "视图名": {
    "param": "<播出后天数，空字符串表示全部>",
    "includes": ["字段1", "字段2"]
  }
}
```

可用视图：
- **版权视图**：`疑似侵权量趋势`
- **星舟视频视图**：`新增预约人数趋势`、`腾讯最新热度值趋势`
- **短音视图**：`短音爆款视频数日新增趋势`、`短音话题播放量日新增趋势`、`短音热点榜数量趋势`
- **猫眼视图**：`猫眼实时热度趋势`、`猫眼实时热度排名趋势`、`全网曝光日新增趋势`、`全网转赞评日新增趋势`
- **微博视图**：`微博话题阅读量日新增趋势`、`微博话题讨论量趋势`、`昨日微博指数趋势`

**调用示例**：

> 📌 下例只演示**参数结构**，`domain_knowledge`/`query`均为**占位、禁止照抄**——实际取值见 `references/kb_recall.md`（成功取自 `<text>`；Fallback 才用影库知识库默认索引名）。

```bash
# 结构骨架（condition/range/rank/target/match 的写法）
mcporter call 'szabot_tools.kb_search(
  recall_req_list: [{
    domain_knowledge: "<取自 kb-recall <text>，勿照抄>",
    query: {
      condition: [{"管理状态": ["已上线", "已播完"]}, {"剧集分类": ["电视剧"]}],
      range: [{"播出时间": ["2025-01-01", "2025-12-31"]}],
      rank: [{"腾讯最高热度值": ["从大到小"]}],
      target: ["<取自 kb-recall <text> 的全量字段，勿照抄此列表>"],
      match: "exact"
    }
  }]
)' --output json

# 并行查多个库：recall_req_list 放多个元素，各带自己的 domain_knowledge（均取自 kb-recall <text>）

# 视图查询（热度趋势用）
mcporter call 'szabot_tools.kb_search(
  recall_req_list: [{
    domain_knowledge: "<取自 kb-recall <text>，勿照抄>",
    query: {
      condition: [{"项目ID": ["6057"]}],
      view: {"星舟视频视图": {"param": "5", "includes": ["腾讯最新热度值趋势"]}}
    }
  }]
)' --output json
```

## 展示格式规范

> **字段级判定**：每个字段**有有效值就展示，无值就跳过**。"无值"包括：空字符串 / `[]` / `{}` / `null` / 字段不返回 / 值为 `"暂无权限查看"`。模块下所有字段全无值 → 该模块整块不渲染，不输出任何兜底文案。
>
> 字段均为 JSON 结构，**直接读取子字段**即可，禁止再做正则匹配或 `JSON.parse` 二次解析。

### 1. 基础信息

字段范围：除「项目关键进展」三字段外，所有 `kb_search` 返回的字段（核心画像 12 项默认骨架 + 标识 3 项 + 用户问题语义命中的其他字段，详见 § 工具参数定义 ① 默认 target 与 ② 宽取原则）。

按字段语义直接铺底展示（表格 / 段落 / 列表，按问题类型选择最直观的形式），不附加额外板块标题。

### 2. 项目关键进展

板块标题：`### 📍 项目关键进展`。

**渲染条件**（同时满足才渲染整块，否则字段仍取回但板块不输出）：
- 场景为「项目基础信息」（其他场景如播放效果、合同、决策会、舆情、选角、排播等一律不渲染）
- `kb_search` 返回正好 1 个候选（项目ID 唯一）
- 下列三字段中**至少一个**有有效值

#### 项目关键制作进度

数组，取第一个元素。子字段：`name`（节点简述）/ `text`（正文）/ `url`（跳转链接）

```
**项目关键制作进度**：{text}，点击查看详情「[{name}]({url})」
```

#### 项目举灯

数组，多条全部展开。子字段（**snake_case 小写**）：`level`（红/黄/绿灯）/ `type`（中台/运营/制片人举灯）/ `statement`（**逐字透传**）/ `operator` / `operate_time`

**排序**：① `level` 红>黄>绿；② `operate_time` 倒序。

```
**项目举灯**：项目当前为 {最高级别}灯
- 【{type}-{level}】{statement} - {operator} {operate_time}
- 【{type}-{level}】{statement} - {operator} {operate_time}
```

#### 项目进展

单个对象（**不是数组**）。子字段：`progress`（正文）/ `user`（录入人）/ `gmt_create`（录入时间）

`progress` 渲染前先剥除开头的 `举灯级别：<颜色>；\n` 前缀（正则 `^举灯级别：[^；]*；\n?`）。

```
**项目进展**：{progress 剥除前缀后的正文} - {user} {gmt_create}
```

## 链接判定（@reference）

`kb_search` 返回结果后，**必须按链接判定规则**判定。

### 项目链接

- target 必须含 `"项目ID"`、`"项目详情链接"` 字段
- 链接格式：`[项目ID](项目详情链接)`；`项目详情链接` 为空时只输出纯文本项目ID
- 有表格时，项目ID**必须放在表格内**作为一行，禁止单独列在表格外
- 不需要判断剧集分类、不需要手动拼接 URL

## 输出检查清单

> 通用检查项（数据来源、严禁编造、主动补充、搜索回退）见 SKILL.md 执行流程第 5 步，以下为本场景特化检查项：

| # | 检查项 | 要求 |
|---|--------|------|
| 0 | ⛔ **续读硬闸** | 作答前确认：问题若想了解项目**进展/情况/制片相关**（"进展如何/怎么样了"这类泛问即达门槛，**只看意图、无需用户点名具体维度**），是否已叠加读取并执行 `references/scene_production_management.md`？**否则不得结束**（详见文首「续读硬闸」） |
| 1 | ⛔ **项目链接** | `项目详情链接` 非空则展示，`[项目ID](项目详情链接)` 格式 |
| 2 | 📍 **target 取值** | 取值方式一律见 `references/kb_recall.md`（成功→全量取自 `<text>`；Fallback→查 `project_fields.md`）。本场景仅额外保证：标识 3 项 `项目ID / 项目名称 / 项目详情链接` 必带；用户未指定字段时带回「项目关键进展」3 字段（`项目关键制作进度 / 项目举灯 / 项目进展`）用于渲染 |
| 3 | 📍 **项目关键进展板块渲染** | 项目ID唯一 + 三字段至少一个有数据 时渲染；否则板块整块跳过（字段仍取回） |

## 常见错误速查

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| `condition: [{"field": "项目名称", ...}]` | `condition: [{"项目名称": ["庆余年"]}]` | ⛔ **最高频错误！** |
| `condition: [{"项目名称": "庆余年"}]` | `condition: [{"项目名称": ["庆余年"]}]` | value 必须是数组 |
| `search_web(query: "...")` | `search_web(keyword: "...")` | 参数名是 keyword |
| `rank: ["腾讯最高热度值", "从大到小"]` | `rank: [{"腾讯最高热度值": ["从大到小"]}]` | rank 是 object[] |
| `view: {"疑似侵权量趋势": true}` | `view: {"版权视图": {"param": "", "includes": ["疑似侵权量趋势"]}}` | view 有固定嵌套结构 |

## Gotchas

- **condition 格式**：模型极容易用 `field/operator/value` 结构，这是**完全错误**的！正确格式是 `{字段名: [值数组]}`
- `search_web` 参数名是 `keyword`，不是 `query`
- range 日期过滤不可靠，用管理状态 + 客户端二次过滤
- `kb_search` view 视图字段可能返回空，Fallback 用 `search_web`
- 字段名必须来自 kb-recall 返回（Fallback 时精确匹配 `project_fields.md`），常见错误：首播时间→播出时间，评分→豆瓣评分，热度→腾讯最高热度值
- 项目名搜不到时可能是续集/别名，先精确→模糊→`search_web` 确认正式名→重搜
