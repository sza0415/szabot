# reference — 制作管理（阶段进度 / 制片）

> 本场景覆盖：**制作中项目（立项到上线）的制片管理类问题** —— 项目处于什么阶段、资料是否齐全、有没有风险、是否超支/超期、片方与核心主创/技术工种产能、资金管理、质量、审查政策、奖励政策、编审/审查进度、交片进度、结算等。
>
> 面向 GM（全量）/ AGM（分工作室）/ 制片支持中心（全量）的制片视角追问。核心思路：**按项目所处「进度阶段」组织回答**，而非平铺字段。

## 场景路由

> 🧱 **底座 + 补充模型（本场景核心，贯穿全篇）**：本场景 = 「项目基础信息」(底座) **+** 阶段化制片数据(补充)，**叠加而非二选一**。前置 `kb_search` 同时承担基础信息底座（项目画像 + 「📍项目关键进展」举灯/进展），`query_production_decision_context` 在其上叠加制片阶段数据，两者融合作答。命中本场景时前置 `kb_search` 已覆盖基础信息层，**无需再单独走「项目基础信息」场景**；若拿不到 `项目ID` 或接口无制片数据，至少保留基础信息层回答，不空手而归。

- **制作管理 / 制片情况查询** → ① `kb_search`（拿 `项目ID` + 项目画像 + 项目关键进展，**即基础信息底座**）→ ② `query_production_decision_context`（按阶段→类别叠加制片数据）→ ③ 对 `data_status=external_skill` 的类别，**你自己**按「external_skill 路由判定」（阶段+类别，**不依赖 `next_actions`**）在本轮继续调用对应 skill 补齐（**拍摄期的拍摄进度/预算/超支/角色进度必须自主续查 `szabot-data-query`，不得让用户再问**，详见下「拍摄期 case」）→ ④ 基础信息与制片数据融合作答。

> ⛔ **强制前置（MANDATORY）**：`query_production_decision_context` 的入参 `project_id` 是**影库项目 ID**，必须先用 `kb_search` 由项目名换取 `项目ID`，**严禁凭记忆/猜测填写 `project_id`**。上下文已带项目 ID 时可直接使用，无需重复 `kb_search`。

### 与相邻场景的消歧

> 按下表判定（"底座+补充"关系见上 🧱）：

| 用户意图 | 处理方式 |
|---------|---------|
| 制片管理细节/判断："有没有风险""超支/超期""全剧本齐不齐""产能/资质""审查·奖励政策""编审进度""交片进度""结算"，或要求按阶段全面盘点 | **底座 + 本场景补充**：`kb_search` 拿画像/关键进展 → 叠加 `query_production_decision_context` |
| 模糊问法："XX项目怎么样了""有没有风险" | 同上，**默认叠加本场景**（覆盖更全）；接口无 `项目ID`/无制片数据时，仅以基础信息层作答 |
| 仅要进展快照 / 基本资料 / 演员 / 导演 / 单纯看举灯 | 只需 `scene_project_core.md`（基础信息底座），**无需叠加本场景** |
| 只问立项/开机**决策会**信息（上会主题、会议状态、阐述页） | `scene_project_meeting.md`（决策会查询） |
| 只问后期/视效**素材制作量化**数据 | 本场景的后期进度类别会给 `next_actions`，按指引追加 `szstudio-cms-board`（见 `scene_scheduling.md`） |
| 只问 IP 权益/合同条款 | `scene_ip_contract.md`（本场景权益类别不足时也会 `next_actions` 指向它） |

## 工具参数定义

> ⚠️ **本文档为工具参数的唯一权威来源**。调用前以本文档为准，忽略 `mcporter list` 的签名描述。

### `kb_search` — 取项目 ID（前置）

完整参数定义见 `references/scene_project_core.md`。本场景用它拿到 `项目ID`，并**一并取回「项目关键进展」三字段**用于结合回答：

```bash
mcporter call 'szabot_tools.kb_search(
  recall_req_list: [{
    domain_knowledge: "影库知识库-ES-0",
    query: {
      condition: [{"项目名称": ["焕羽"]}],
      target: ["项目ID", "项目名称", "项目详情链接", "管理状态", "开发状态", "剧集分类",
               "项目关键制作进度", "项目举灯", "项目进展"],
      match: "exact"
    }
  }]
)' --output json
```

> 同时取回 `项目详情链接` 用于回答时的链接展示（链接判定见下文）；`项目关键制作进度 / 项目举灯 / 项目进展` 用于结合制片数据回答（见「业务规则 · 结合项目关键进展」）。

### `query_production_decision_context` — 项目阶段上下文（制片数据）

按「项目进度阶段 → 数据类别」返回制片相关数据，供直接消费回答。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | `string` | **是** | 影库项目 ID（来自前置 `kb_search` 的 `项目ID`）。为空时**禁止调用** |
| `stage_names` | `string[]` | 否 | 指定要查看的进度阶段，**中文**。为空时服务端自动判定当前阶段并返回 |

**`stage_names` 合法枚举**（服务端支持同义词归一化，如"立项/开机/决策"→决策阶段）：

```
"决策阶段（立项+开机）"、"拍摄期"、"杀青至交片前"、"过审待播"、"播后"
```

**入参选择策略**：
- 用户**笼统**问"项目怎么样了 / 有没有风险 / 项目进度" → **只传 `project_id`**，让服务端自动判定当前阶段。
- 用户**点名某阶段/类别**（如"编审进度怎么样""决策阶段资料齐不齐""过审待播交片情况"）→ 传对应 `stage_names`（中文，可多值）。

**调用示例**：

```bash
# ① 笼统问进度 —— 自动判定当前阶段
mcporter call 'szabot_tools.query_production_decision_context(
  project_id: "308"
)' --output json

# ② 指定阶段查询
mcporter call 'szabot_tools.query_production_decision_context(
  project_id: "308",
  stage_names: ["决策阶段（立项+开机）"]
)' --output json

# ③ 一次查多个阶段
mcporter call 'szabot_tools.query_production_decision_context(
  project_id: "308",
  stage_names: ["决策阶段（立项+开机）", "杀青至交片前"]
)' --output json
```

## 响应结构与消费

返回核心结构（中文阶段名/类别名直接面向阅读，**不要再翻译成英文枚举**）：

```text
project          # 项目元信息：project_name / category / management_status / pstatus / apply_id(评估单ID) / roc_id
current_stage    # 服务端判定的当前阶段：stage_name / stage_reason
stage_contexts[] # 按阶段组织
  stage          # 阶段名 + 判定理由
  is_current     # 是否当前阶段
  categories[]   # 该阶段下的类别块
    category_name  # 资料 / 权益 / 审查政策 / 预算 / 风险 / 拍摄进度 / 后期进度 / 编审进度 / 交正片进度 / 结算 / 奖励政策
    data_status    # available / partial / external_skill / missing / denied
    fields[]       # 键值数据（name/value）：适合资料、审查意见摘要等
    records[]      # 列表数据（name/record_type/fields[]）：适合权益项、政策候选、成本科目等
    next_actions[] # 建议追加调用的外部工具/skill（name/reason/suggested_source/input_keys）
missing_data[]   # 需要但未取到的数据
denied_data[]    # 因权限不可见的数据
```

### `data_status` 处理规则（背诵级）

| 状态 | 含义 | 回答处理 |
|------|------|---------|
| `available` | 本接口已返回完整数据 | 直接读 `fields`/`records` 总结 |
| `partial` | 部分返回，仍需其它工具补齐 | 先总结已返回部分，再按 `next_actions` 追加调用补齐 |
| `external_skill` | 本类别由其它工具/skill 负责（`fields` 常只写"由其他 skill 处理"，`next_actions` **可能为空**） | **不要编造**；**你自己**在本轮继续调用对应 skill 补齐（不要让用户再问）。**即使 `next_actions` 为空、说明含糊，也必须按"阶段 + 类别"自行判定该调哪个 skill**（见下「external_skill 路由判定」），不得因没有明确指向就跳过或收尾 |
| `missing` | 当前无稳定数据源 | **不要编造/脑补**；如实说明"该项暂无稳定数据源" |
| `denied` | 无权限 | 说明"无权限查看"，不展示，不臆测 |

> ⚠️ **接口未返回的类别 = 无稳定数据源**，对未返回的数据**一律不得编造**。

### `external_skill` 路由判定（**不依赖 `next_actions`**）

> ⚠️ 接口对 `external_skill` 类别**经常返回空的 `next_actions`**（仅 `fields` 写"由其他 skill 处理"）。**不要等 `next_actions.suggested_source`**——按下表"**阶段 + 类别**"自行判定该调哪个 skill，主动续查：

| 阶段 + 类别 | 应调用 | 说明 |
|---|---|---|
| **拍摄期** 的 拍摄进度 / 预算 / 超支 / 角色进度 / 进度异常 / 延期 | ⛔ **`szabot-data-query` Skill** | 见下「拍摄期 case」。⚠️ 拍摄进度 ≠ 后期进度，**不要错调 `szstudio-cms-board`** |
| **杀青至交片前** 的 后期进度 / 视效素材制作量化 | `kb_search`（后期字段）+ `szstudio-cms-board` | 详见 `scene_scheduling.md` |
| 任意阶段的 IP 权益 / 合同补齐 | `ip_right_search` / `ip_info_search` / `contract_search` | 详见 `scene_ip_contract.md` |

> 📌 **破除误区**：`szabot-data-query` **不只是播放/收入/成本统计**——它同时承载**拍摄期的制片量化数据**（拍摄进度、预算执行、超支科目、角色进度等）。拍摄期问"进度/怎么样了/有没有超支"，就该走它。
> 若 `next_actions` 恰好非空，按其 `input_keys` 填参即可，但**它为空不影响上表判定**。

### ⛔ 拍摄期 case（拍摄进度 / 预算 / 超支 / 角色进度 / 进度异常 / 延期）

> **触发条件（满足其一即触发，不依赖 `next_actions`）**：① `current_stage = 拍摄期`；或 ② 拍摄进度/预算/超支/角色进度等类别 `data_status = external_skill`（**哪怕 `next_actions` 为空、`fields` 只写"由其他 skill 处理"**）。此时这些数据**本接口不产出，统一交给 `szabot-data-query` Skill 的制片查询能力**。
>
> ⚠️ 别混淆：这里是**拍摄期的「拍摄进度」**，走 `szabot-data-query`；**杀青后的「后期/视效进度」**才走 `szstudio-cms-board`。两者不要互换。

> 🤖 **自主执行（最重要）**："交给 `szabot-data-query`"指的是**你（LLM）在本轮对话内自己继续加载并调用 `szabot-data-query` 完成查询**，把结果接着答出来。**严禁中断、严禁让用户"自行去查/再次提问/换个问法"**——用户已经问过了，无需再确认。除非 `szabot-data-query` 真的不可用（见第 5 条兜底），否则必须一气呵成地把数据查到并融合作答。

**协作契约（只约定跨 Skill 边界，不复制 `szabot-data-query` 的内部实现）**：

1. **触发条件**：需要拍摄进度 / 预算执行 / 超支科目 / 角色进度 / 进度异常 / 延期等制片量化数据时。
2. **入参透传**：把前置 `kb_search` 取得的 `项目ID` 透传给 `szabot-data-query`，由其据此查询；**禁止用 SQL 反查项目ID**。
3. **执行方式**：**由你主动加载并按 `szabot-data-query` 自身的 SKILL/reference 流程执行**（这是你的下一步动作，不是给用户的建议）——具体的库表、字段、SQL 模板、MCP 工具、展现模板**一律以 `szabot-data-query` 为准，本文件不复制、不固化**（避免其升级后此处失效）。本文件只负责把任务"路由"过去。
4. **融合作答**：把 `szabot-data-query` 返回的拍摄/预算数据，与本接口已返回的「风险」类别、以及基础信息底座的「项目关键进展（举灯）」融合，给出拍摄期的进度/超支/风险综合判断。
5. **不可用兜底**：仅当 `szabot-data-query` 确实不可用（服务/MCP 异常）时，才如实说明"拍摄期进度/预算需经制片数据查询获取，当前不可用"，**禁止编造进度或预算数字**；即便如此也不要把查询动作推给用户。

## 业务规则

### 阶段 → 默认类别（用于组织回答）

| 项目进度阶段 | 默认类别 | 本接口数据情况 |
|---|---|---|
| 决策阶段（立项+开机） | 资料、权益、审查政策、预算、风险 | 本接口**直接返回** |
| 拍摄期 | 拍摄进度、预算、风险 | 拍摄进度/预算/超支/角色进度标为 `external_skill` → **委托 `szabot-data-query` Skill**；风险按字段汇总 |
| 杀青至交片前 | 后期进度、审查/编审进度、风险 | 后期进度/编审进度来自电视剧知识库字段 |
| 过审待播 | 交正片进度 | 暂无稳定制片数据源，多为空，`stage_reason` 会标注 |
| 播后 | 结算、奖励政策 | 结算暂无稳定源；奖励政策可返回政策配置或 `next_actions` |

### 按阶段回答的组织逻辑（制片视角 SOP）

0. **先铺底座**：用前置 `kb_search` 的项目画像 + 「📍项目关键进展」给出项目概况与最新进展（基础信息层，几乎必给）。
1. **再点明项目当前阶段**（`current_stage.stage_name` + 必要时 `stage_reason`）。
2. **按该阶段的类别逐项叠加说明**，每个类别只讲该阶段关心的事：
   - 决策阶段：资料（是否全剧本、未提交全剧本原因）/ 权益（剧集权益、剧集改编权、IP 改编权）/ 审查政策（编审意见、过审难度、重点省局扶持、奖励政策）/ 预算（决策会预算评估结论、可下调科目）/ 风险（片方资质、片方与主创产能）。
   - 拍摄期：拍摄进度（时间/场次/页数）/ 预算执行与科目超支预警 / 角色进度 / 进度异常·延期 / 风险（一二级供应商新增风险）。⛔ 拍摄进度·预算·超支·角色进度等**委托 `szabot-data-query` Skill**（见「拍摄期 case」），本接口仅汇总风险字段。
   - 杀青至交片前：后期/视效进度、编审/审查进度、风险。
   - 过审待播：交正片进度（已交付集数、质检报告）。
   - 播后：结算（纠纷、历史项目抵扣）、奖励政策。
3. **对 `available`/`partial` 数据直接总结**；对 `external_skill` 按「external_skill 路由判定」（阶段+类别，不依赖 `next_actions`）主动续查对应 skill 后再补充；对 `missing`/未返回数据**如实说明无数据源，禁止编造**。
4. **意图叠加**（见 SKILL.md 执行流程第 1 步）：
   - 问"有没有风险/怎么样" → 给方向性判断（有/无明显风险、风险点是什么），不要只罗列字段。
   - 问"为什么/原因" → 内部数据不足以解释时追加 `search_web`。
   - 问"建议"（如最优备案地、可争取奖励金额区间）→ 基于政策类别数据给可操作建议；高质量/主旋律项目通常更易获奖励，金额可给区间建议。

### 结合项目关键进展回答

前置 `kb_search` 取回的「项目关键进展」三字段是**制片数据的有力补充**，可与 `query_production_decision_context` 的阶段类别数据**交叉印证、融合作答**（而非各说各话）：

- **项目举灯**（`项目举灯`）：最能反映**风险与状态信号**。
  - 字段为数组，多条全部参考；子字段 `level`（红/黄/绿灯）/ `type`（中台/运营/制片人举灯）/ `statement`（**逐字透传**）/ `operator` / `operate_time`。
  - 排序：① `level` 红>黄>绿；② `operate_time` 倒序。
  - 回答"有没有风险"时，**优先看举灯**：有红/黄灯 → 明确点出风险等级 + `statement` 原文 + 举灯人/时间，并与接口返回的风险/预算/进度类别结合；全绿灯或无举灯 → 说明"暂无举灯预警"。
- **项目关键制作进度**（`项目关键制作进度`）：数组取第一个元素，子字段 `name`/`text`/`url`，可作为阶段进度的**一句话锚点**，与阶段类别进度互为印证。
- **项目进展**（`项目进展`）：单个对象，子字段 `progress`（渲染前剥除开头 `^举灯级别：[^；]*；\n?` 前缀）/ `user` / `gmt_create`，作为最新进展补充。

> 三字段的取值/渲染细节以 `references/scene_project_core.md` 的「§ 项目关键进展」为准（举灯排序、进展前缀剥除等规则一致）。
>
> **融合原则**：举灯/进展与接口的阶段类别数据**指向一致**时，合并成一个结论（如举灯黄灯+预算科目超支预警 → 统一表述为"存在超支风险"）；**冲突或互补**时分别呈现并说明来源。**字段无值则跳过，不输出兜底文案**。

### 奖励政策回答口径

- 政策候选（`records`，`record_type=policy_candidate` 等）按"备案地 + 可获得金额/区间 + 适用条件（题材/风貌/古装现代）"组织。
- 可给"推荐最优备案地 + 预估金额区间"的**建议性**结论，并说明依据；无明确金额时给区间或定性建议，**不要编造精确数字**。

## 链接判定（@reference）

前置 `kb_search` 已取回 `项目ID` / `项目详情链接`，回答涉及项目时按通用规则展示：

- 链接格式：`[项目ID](项目详情链接字段值)`；`项目详情链接` 为空时只输出纯文本项目 ID。
- 有表格时项目 ID 必须放在表格内一行，禁止单列在表格外。

## 输出检查清单

> 通用检查项（数据来源、严禁编造、主动补充、搜索回退）见 SKILL.md 执行流程第 5 步，以下为本场景特化检查项：

| # | 检查项 | 要求 |
|---|--------|------|
| 1 | ⛔ **先取 project_id** | 调 `query_production_decision_context` 前必须已有影库 `项目ID`（来自 `kb_search` 或上下文），禁止猜测 |
| 2 | ⛔ **按阶段组织** | 回答先点明当前阶段，再按阶段下类别逐项说明，禁止平铺一堆字段 |
| 3 | ⛔ **不编造** | `external_skill`/`missing`/未返回 的类别一律不得编造；`external_skill` 须**你自己**继续调用对应工具补齐（不要让用户再问），仅工具不可用时才如实说明 |
| 4 | ⚖️ **意图覆盖** | 问"有没有风险/怎么样"给方向判断，问"建议/奖励/备案地"给可操作建议（金额可给区间） |
| 5 | 🚦 **结合项目关键进展** | 前置 `kb_search` 已取回 `项目举灯/项目关键制作进度/项目进展`；回答风险/进度时优先结合**举灯**信号（红/黄/绿）与接口阶段数据融合作答，字段无值则跳过 |
| 6 | 🎬 **拍摄期自主续查** | 拍摄期的拍摄进度/预算/超支/角色进度等，**你必须在本轮自主继续调用 `szabot-data-query` 查询并融合作答**，本接口不直接拉；**禁止让用户自行去查/再次提问**，也禁止用 `query_production_decision_context` 编造拍摄进度 |
| 7 | 🔗 **项目链接** | 涉及项目时 `[项目ID](项目详情链接)` 格式展示 |

## 常见错误速查

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| `query_production_decision_context(project_id: "焕羽")` | 先 `kb_search` 拿到数字/正式 `项目ID` 再传 | `project_id` 是影库项目 ID，不是项目名 |
| `stage_names: ["决策阶段"]`（漏全称） | `stage_names: ["决策阶段（立项+开机）"]` | 用合法中文枚举；服务端虽支持归一化，但优先用标准名 |
| `stage_names: "拍摄期"` | `stage_names: ["拍摄期"]` | 值必须是数组 |
| 对 `external_skill` 类别直接编造进度/预算 | 按 `next_actions` 追加调用或如实说明 | 严禁脑补 |
| 用户笼统问进度却强行指定阶段 | 只传 `project_id`，让服务端判定当前阶段 | 笼统问 = 自动判定 |

## Gotchas

- **必须两步走**：`kb_search`（拿 `项目ID`）→ `query_production_decision_context`。两步无依赖冲突可在拿到 ID 后顺序调用。
- **中文入参**：`stage_names` 用中文阶段名，响应里的 `stage_name`/`category_name` 也是中文，直接面向阅读，不要翻译成英文枚举。
- **接口未返回 ≠ 值为空**：未返回某类别说明无稳定数据源（本地仅记日志），不要据此罗列"暂无数据"误导用户，更不能编造。
- **过审待播 / 播后**：当前多无稳定制片数据源，接口会在 `stage_reason` 标注"暂无对应的制片相关数据"，如实转达即可。
- **后期进度类别**：若返回 `external_skill` 或数据不足，按 `scene_scheduling.md` 追加 `szstudio-cms-board` 获取素材制作量化数据。
- **拍摄期进度/预算/超支/角色进度**：本接口标 `external_skill`，**强制委托 `szabot-data-query` Skill**——规则见上「拍摄期 case」（单一权威源）。
- **权益/合同不足**：决策阶段权益类别只给基础项时，按 `next_actions` 追加 `scene_ip_contract.md` 的 `ip_right_search`/`ip_info_search`/`contract_search` 补齐。
