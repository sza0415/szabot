# reference — 综合分析

> **本场景覆盖**：复盘、好剧推荐、营销推广、行业分析、项目预测、播放效果与收入、项目分析/建议类
>
> ⛔ **必读**：`kb_recall` 的调用方式、两段式流程、取值铁律、Fallback SOP 全部在 `references/kb_recall.md`。**本文件不复述该内容**，构造 `kb_search` 参数前请先读 `kb_recall.md`，否则会出现"把 `kbcli kb-recall`（CLI）当成 `szabot_tools.kb_recall`（MCP）来调"、"跳过 Step 2 直接 Fallback"、"domain_knowledge 凭记忆写死"等已知失败模式。

## 场景路由

- **复盘** → 并行调用 `kb_search` + `report_search` + `search_web`（三者入参均来自项目名称，无依赖，同时发起）
- **好剧推荐** → `kb_search`（管理状态=已上线/已播完，rank 按热度降序）
- **营销推广** → `@expert:market`
- **项目分析/建议类** → `kb_search` → **[按需]** `script_search`（涉及剧情/拍摄/特效场景时）→ **[推荐]** `search_web`（行业案例、技术方案、最佳实践）
- **行业分析** → `kb_search`（聚合数据）+ `search_web`（行业报告）
- **项目预测** → `kb_search`（目标项目 view）→ `kb_search`（同类型爆款）→ 对比
- **播放效果与收入** → ⛔ 强制按以下步骤执行，禁止跳过任何一步：

  > 📌 **本场景识别词（不区分剧集分类，电视剧/综艺/电影/短剧均适用）**：
  > - 电视剧/电影常用：播放怎么样、播得怎么样、播放情况、热度怎么样、数据如何、播出表现、播得好不好、表现怎么样、收视如何
  > - 综艺常用：节目效果、节目反响、节目播得怎么样、节目热度、播出反响、口碑如何、有多火、上线表现
  > - 通用：播放数据、收入怎么样、ROC、出圈情况
  >
  > ⚠️ 上述词为示例，按**语义判断**而非字面匹配。只要用户在问某项目"上线后表现/数据/反响"，无论电视剧还是综艺，均属于本场景。

  - `[Phase-1] 并行调用`（三者入参均来自用户原始查询，无相互依赖，**必须在同一个 tool_use 响应中同时发起 3 个调用**）：
    - `kb_search` — 获取项目基础信息（**项目ID、剧集分类、ROC、总收入、项目详情链接、项目日报链接** 等）
    - `report_search` — 查询舆情/口碑数据（**即使返回空也必须调用**）
    - `search_web` — 补充公开播放数据和最新动态（即使 `report_search` 有数据也必须调用）
    > ⚠️ **并行要求**：禁止先调 `kb_search` 等返回后再调另外两个，这会多浪费一轮推理 + 网络往返（~7s）。三个工具的入参都只依赖用户原始输入的项目名称，必须**同一轮**发起。
  - `[Phase-2] get_project_report`（依赖 Phase-1 拿到的项目ID）：
    - 调用 `szabot_tools.get_project_report(project_id: "<项目ID>")` 拉取项目日报数据，**作为播放/反响分析的核心数据源**
    - ⛔ **触发条件（务必执行）**：本场景下，只要 `kb_search` 返回了项目ID，**就必须调用** `get_project_report`，**电视剧、综艺、电影、短剧一视同仁**，禁止以"综艺可能没有日报"等理由主动跳过
    - ⚠️ `project_id` 是**字符串**类型（如 `"2142"`），不是数字；也不要传项目名称
    - 唯一可跳过的情况：`kb_search` 完全没返回项目ID（项目不存在）
    - 若调用返回为空 / 报错，回退到仅基于其他数据源回答，并在「📋 数据引用」段注明"项目日报暂无数据"
  - `[Phase-3]` ⛔ 等待 Phase-1 / Phase-2 全部返回后，切换到 `skill:szabot-data-query` — **透传用户原始查询意图**，补充播放漏斗详细数据（曝光VV/UV、正片VV/UV、有效播放UV、完播率、留存率、拉新、弹幕、预估VV 等）
  - ⚠️ **电视剧 ROC 规则**：当前在播项目只看「新ROC2（vv）」「新ROC2（ul）」（成对使用），`kb_search` 返回 ROC1、ROC2 为空属于正常（仅早期项目有值），**禁止**因此追加 `decision_making_meeting_search` 查 ROC，也**禁止**在回答中提示"ROC1/ROC2 暂无数据，需通过决策会查看"
  - ⚠️ **收入字段 target 构造规则**：当用户提及"收入"相关信息时，`kb_search` 的 `target` 必须包含以下字段（全部加入，返回中没有对应 key 的字段说明无数据，输出时跳过即可）：
    - 总收入、会员收入、广告收入、分销收入、发行收入、IP增值收入、其他收入、新ROC2（vv）、新ROC2（ul）、豆瓣评分、腾讯最高热度值
  - ⚠️ **target 链接字段固定要求**：本场景 `kb_search` 的 `target` **必须同时包含** `"项目ID"`、`"项目详情链接"`、`"项目日报链接"` 三个字段（缺哪个都拿不到对应链接）
  - ⚠️ **输出规范**：分析正文之后，按「链接判定」段输出链接（项目详情链接、项目日报链接独立判定，**返回了几个就输出几个**），并按「数据引用规范」段汇总「📋 数据引用」。

### 「爆梗/出圈内容」场景识别规则（MANDATORY）

当用户问某剧的"爆梗"、"出圈内容"、"名场面"、"经典桥段"等内容元素时，必须区分**回顾性**和**前瞻性**两种意图：

| 判断依据 | 回顾性（舆情口碑） | 前瞻性（内容挖掘） |
|---------|-------------------|-------------------|
| 关键词 | "有什么爆梗"、"出圈了什么" | "有出圈**潜质**"、"可能出圈"、"值得营销的内容"、"适合做二创的内容" |
| 时态 | 已播出、已有讨论 | 未播/待播、预测性、挖掘性 |
| 数据来源 | 舆情报告 + 网络搜索 | **剧本内容**（`script_search` 必调） |
| 路由 | 走「舆情口碑」路由 | 走「内容挖掘」路由（`script_search` → `kb_search` → `search_web`） |

**核心判断逻辑**：如果用户措辞包含"潜质"、"可能"、"适合"、"值得"等**前瞻性/预测性**词汇，说明用户需要从剧本内容本身挖掘出圈元素，而非回顾已有舆情。此时 `script_search` 是**必调工具**。

> 即使项目已播出，只要用户问的是"哪些内容有出圈潜质"而非"已经出圈了什么"，也应走「内容挖掘」路由。

### 项目分析/建议类场景说明

对某项目提出分析性/建议性问题（如"后期难点"、"AI降本"、"制作挑战"、"如何优化"、"适合什么类型观众"），与单纯查进度不同，此类问题需要内部数据（项目信息+剧本内容）作为分析基础，再结合 `search_web` 补充行业最佳实践和案例。

> ⚡ **并发优化**：当涉及剧情/拍摄/特效场景时，`kb_search` 和 `script_search` 入参均来自项目名称，无相互依赖，可在**同一轮**并行发起；`search_web`（行业案例）也可同时并发调用。

> ⛔ **输出规范**：分析/建议类问题**直接输出分析结论和建议**，禁止在回答开头展示项目基础信息表格（如项目ID、管理状态、开发状态、制片人、工作室等）。项目信息仅作为内部查询的上下文依据，不作为回答内容输出。用户问的是"分析"和"建议"，不是"项目信息"。

## 工具参数定义

> ⚠️ **本文档为工具参数的唯一权威来源**。`mcporter list szabot_tools` 返回的参数类型定义存在错误，**调用工具时必须以本文档为准**。

> ℹ️ `kbcli kb-recall` 是 CLI（不是 MCP 工具，`mcporter list` 不会列出），调用方式见 `references/kb_recall.md`。

### `kb_search` — 项目检索

影库数据库核心工具，支持多知识库并行。通过 `recall_req_list` 传入检索请求，`domain_knowledge` 取值遵循 `references/kb_recall.md` 取值铁律（首选 kb-recall 返回值，兜底从 scene reference 文件中取）。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `recall_req_list` | `object[]` | **是** | 检索请求列表，每个元素含 `domain_knowledge`（库标识字符串）和 `query`（查询参数） |

**`query` 内部参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `condition` | `object[]` | 否 | 等值筛选条件，多个条件之间为 AND 关系。字段名来自 `kbcli kb-recall` 返回，Fallback 时查 `references/project_fields.md` |
| `range` | `object[]` | 否 | 区间筛选 |
| `rank` | `object[]` | 否 | 排序规则 |
| `target` | `string[]` | 否 | 要返回的字段列表 |
| `match` | `string` | 否 | `"exact"` 或 `"fuzzy"`，默认精确匹配 |
| `view` | `object` | 否 | 视图查询（用于热度趋势、侵权趋势等） |

#### view 参数详细格式（项目预测必用）

```
view: {
  "视图名": {
    "param": "<播出后天数，空字符串表示全部>",
    "includes": ["字段1", "字段2"]
  }
}
```

可用视图：
- **版权视图**：`疑似侵权量趋势`
- **星舟视频视图**：`新增预约人数趋势`、`腾讯最新热度值趋势`
- **短音视图**：`短音爆款视频数日新增趋势`、`短音话题播放量日新增趋势`、`短音热点榜数量趋势`
- **猫眼视图**：`猫眼实时热度趋势`、`猫眼实时热度排名趋势`、`全网曝光日新增趋势`、`全网转赞评日新增趋势`
- **微博视图**：`微博话题阅读量日新增趋势`、`微博话题讨论量趋势`、`昨日微博指数趋势`

#### target 字段构造 SOP（遵循 `references/kb_recall.md` 取值铁律）

**kb-recall 成功时（返回 `<text>`）**：target **必须传入 kb-recall 返回表格中"字段中文名"列的全部值**——不增、不删、不换、不筛选，禁止从本文件示例或默认列表补充/替换字段。

**仅 Fallback 时（kb-recall 失败/返回空）**，按以下 SOP 构造 target：

**① 必含字段** — `target` 中**必须包含 `"项目ID"` 和 `"项目详情链接"`**，即使用户未主动要求。`项目ID` 用于数据关联及链接展示文本，`项目详情链接` 字段由 MCP 服务直接返回项目链接 URL（非空即为有效链接）。播放效果类问题还应额外包含 `"项目日报链接"`。

**② 宽取原则** — 除非用户**明确列出**要哪些字段，否则**禁止只返回少量字段**。必须在 `references/project_fields.md` 中做"语义扫描"，把所有语义相关的字段全部放进 target。

**③ 构造步骤**：
1. 提取用户问题中的语义关键词
2. 在 `project_fields.md` 中做关键词匹配（字段名、说明栏、简称/别名）
3. 凡命中的字段都加入 target，用户简称/别名必须映射回正式字段名
4. target 体量参考：宁可 15~25 个字段一次取回

### `get_project_report` — 项目日报检索

按项目维度拉取**项目日报**数据，是播放效果类问题（"播得怎么样/播放情况/热度怎么样"）的**核心数据源**。日报内容通常包含：项目当日热度、排名、关键节点、播放亮点、舆论摘要等。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `project_id` | `string` | **是** | 项目ID（**字符串类型**，如 `"2142"`，不是数字）。从 `kb_search` 返回的 `项目ID` 字段获取 |

**调用约束**：
- 必须先用 `kb_search` 拿到项目ID，再用该ID调 `get_project_report`，不要用项目名称直接调
- **触发条件**：用户问播放效果类问题（"播放/反响/节目效果/收入/ROC"等，电视剧、综艺、电影、短剧均适用），且 `kb_search` 返回了项目ID 时**必须调用**——不要因为"综艺可能没日报"等理由主动跳过
- 返回为空 / 报错 → 回退到仅基于其他数据源回答，并在「数据引用」段注明"项目日报暂无数据"

### `report_search` — 舆情报告检索

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keyword` | `string` | **是** | 项目名称关键词，不加书名号 |

> ⚠️ report_search 数据覆盖率有限，常返回空。Fallback → `search_web(keyword: "项目名 口碑/舆情")`

### `search_web` — 网络搜索

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keyword` | `string` | **是** | 搜索关键词 |
| `limit` | `number` | 否 | 返回结果数量，默认 10 |

> ⚠️ 参数名是 `keyword`，**不是** `query`！

## 字段速查（@reference）

构造 condition/range/rank/target 时，字段名优先取自 `kbcli kb-recall` 返回；仅 Fallback 时精确匹配 `references/project_fields.md`。

**本簇常用字段**：
- condition：项目名称、管理状态、剧集分类、合作模式、题材赛道、题材类型、新媒体平台、数据来源、项目评级
- range：播出时间、完结时间
- rank：腾讯最高热度值、总播放VV、豆瓣评分、新ROC2（vv）、新ROC2（ul）、总收入
- target：项目ID、项目详情链接、项目日报链接、主要演员、导演、编剧、管理状态、播出时间、剧集分类、豆瓣评分、腾讯最高热度值、总播放VV、总播放UV、总收入、会员收入、广告收入、分销收入、发行收入、IP增值收入、其他收入、新ROC2（vv）、新ROC2（ul）、题材类型、项目评级

> ⚠️ **电视剧 ROC 取数**：当前项目只看「新ROC2（vv）」「新ROC2（ul）」（成对使用），ROC1/ROC2 为空属于正常现象，**不要**主动展示或提示。

> 📊 完整字段列表见 `@reference references/project_fields.md`

## 链接判定（@reference）

`kb_search` 返回结果后，**必须按链接判定规则**判定是否输出项目链接。

> ⛔ **反幻觉总原则（最高优先级）**：所有链接的 URL **必须原样取自** `kb_search` 返回的字段值（`项目详情链接` / `项目日报链接`）。
> - 禁止根据项目ID **自行拼接** URL（如 `https://szbot.example.com/project/<项目ID>`）
> - 禁止根据本文档的"示例 URL"反推真实 URL 格式
> - 禁止"推测"、"参考类似项目"或"按经验补全"链接
> - 字段值为空 / key 不存在 / 未返回 → **直接不输出该行链接**，不要尝试用任何方式补全

**通用规则**：
- target 必须含 `"项目ID"`、`"项目详情链接"` 字段
- 链接格式：`[项目ID](项目详情链接字段值)`；`项目详情链接` 为空时**只输出纯文本项目ID，不带任何链接**
- 有表格时，项目ID**必须放在表格内**作为一行，禁止单独列在表格外

**播放效果与收入场景（链接独立判定，互不依赖）**：
- target 必须额外含 `"项目日报链接"`
- 在分析正文 / 数据引用之后，**逐字段独立判断是否输出**：
  - 「项目详情链接」字段非空 → 输出 `🔗 项目详情：[<项目名称>](项目详情链接字段值)`
  - 「项目日报链接」字段非空 → 输出 `📊 项目日报：[查看完整日报](项目日报链接字段值)`
- 字段为空 / key 不存在 / 未返回 → 不输出**该行**（不允许编造），但不影响另一行的判断
- 两个字段都未返回 → 两行都不输出，**禁止用项目ID 拼接任何"看似合理"的链接**

## 数据引用规范（@reference）

播放效果类问题的回答常融合多个数据源（`kb_search` 项目字段、`get_project_report` 日报、`report_search` 舆情、`szabot-data-query` 漏斗、`search_web` 公开数据）。**当回答中使用了某一数据源的具体内容时，必须在该处明确标注来源**，便于用户溯源核对。

### 标注规则（MANDATORY）

| 数据来源 | 引用标注方式 |
|---------|-------------|
| `get_project_report` 日报数据 | 句末加 `（来源：项目日报）` 或在该段末尾用引用块写明 `> 数据引用：项目日报（项目ID: <项目ID>）` |
| `kb_search` 项目字段 | 默认数据源，无需逐句标注 |
| `szabot-data-query` 漏斗数据 | 句末加 `（来源：影库数据查询）` |
| `report_search` 舆情数据 | 句末加 `（来源：舆情报告）` |
| `search_web` 公开搜索 | 必要时标注 `（来源：网络公开信息）` |

### 输出格式建议

回答末尾**统一汇总**一段「📋 数据引用」，列出本次回答涉及的数据源，例如：

```
📋 数据引用：
- 项目基础信息 / 收入 / ROC：影库 kb_search
- 播放热度趋势 / 关键节点 / 排播表现：项目日报（get_project_report，项目ID: 2142）
- 播放漏斗（曝光VV、完播率等）：影库数据查询（szabot-data-query）
- 舆情口碑：舆情报告 + 网络搜索

🔗 项目详情：[<项目名称>](<kb_search 返回的「项目详情链接」字段值，原样填入；为空则整行省略>)
📊 项目日报：[查看完整日报](<kb_search 返回的「项目日报链接」字段值，原样填入；为空则整行省略>)
```

> ⚠️ 链接行严格按"链接判定"段执行：URL 必须**原样**取自 `kb_search` 返回的字段值，**严禁**用项目ID 拼接 URL（如 `https://xxx/project/<ID>`），**严禁**编造或推测 URL；字段为空就整行省略。

### 强约束

- ⛔ 当**使用了** `get_project_report` 数据进行分析（哪怕一两句话），就必须在「📋 数据引用」中列出"项目日报"，禁止隐没来源
- ⛔ 禁止把日报数据当作 `kb_search` 的字段一并输出，二者**数据口径和时效不同**
- 若 `get_project_report` 返回为空 / 报错，「📋 数据引用」中显式说明"项目日报暂无数据"

## 项目预测方法

1. 明确目标项目的题材类型
2. 在影库检索近3年2个同类型爆款作为参考
3. 对比目标项目和参考项目的**侵权量绝对值 + 增长斜率**（通过 kb_search view 视图）
4. 判断标准：连续3天超参考项目→有火的潜质；连续3天陡增→60%可能；连续1周超→有爆火可能
5. 所有数据从影库查询，不可假设

## 常见错误速查

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| `condition: [{"field": "项目名称", ...}]` | `condition: [{"项目名称": ["庆余年"]}]` | ⛔ 不是 field/operator/value |
| `condition: [{"项目名称": "庆余年"}]` | `condition: [{"项目名称": ["庆余年"]}]` | value 必须是数组 |
| `search_web(query: "...")` | `search_web(keyword: "...")` | 参数名是 keyword |
| `rank: ["腾讯最高热度值", "从大到小"]` | `rank: [{"腾讯最高热度值": ["从大到小"]}]` | rank 是 object[] |

## Gotchas

- `report_search` 数据覆盖率有限，返回空是常态，要主动用 `search_web` 补充
- `search_web` 参数名是 `keyword`，不是 `query`
- `kb_search` 的 view 视图字段可能返回空，Fallback 用 `search_web`
- view 有固定嵌套结构 `{"视图名": {"param": "", "includes": [...]}}`，不要写成 `{"字段名": true}`
- range 日期过滤不可靠，用管理状态 + 客户端二次过滤
- 若 `search_web` 调用失败，尝试 `szabot-web-search` Skill 的 `mcp_web_search`
- ⛔ **播放效果场景必须 3 阶段走到底**：Phase-1 并行（`kb_search` + `report_search` + `search_web`）→ Phase-2 `get_project_report`（依赖项目ID）→ Phase-3 `szabot-data-query` 漏斗，**任一阶段省略都属于执行错误**；输出阶段按「链接判定」+「数据引用规范」输出双链接和数据来源
- ⛔ **`get_project_report` 触发判断（务必）**：本场景下，只要 `kb_search` 返回了项目ID，**电视剧/综艺/电影/短剧一律调用** `get_project_report`，禁止仅因"综艺可能没日报"或"返回里没看到项目日报链接字段"而主动跳过
- ⛔ **`get_project_report` 参数类型**：`project_id` 是字符串（`"2142"`），不是数字（`2142`）；不要传项目名称
- ⛔ **链接独立判定**：`项目详情链接` 和 `项目日报链接` 各自独立判断输出，**返回了几个就输出几个**——禁止"输出了日报链接就省略详情链接"或"二者都省略"
- ⛔ **链接 URL 严禁编造（高频幻觉点）**：链接的 URL **必须原样**取自 `kb_search` 返回的字段值。常见错误：根据项目ID 拼接 `https://szbot.example.com/project/<id>` 这类"看起来合理"的链接 → **严禁**。字段为空 / 未返回 → **整行省略**，不要试图补全
- ⛔ **使用日报数据必须注明来源**：回答中只要使用了 `get_project_report` 返回的内容，就必须在「📋 数据引用」段列出"项目日报"，禁止与 `kb_search` 字段混淆来源
- ⛔ **缺失字段 key 不罗列**：`kb_search` 返回结果中**完全没有某字段的 key**（而非值为空/N/A）→ 直接跳过、不在输出中以"XX：暂无数据"形式罗列，避免误导用户以为系统有该字段但值为空；若该字段是用户明确询问的核心信息，可在末尾自然地说明"该项目暂未录入XX信息"
  - 区分两种情况：
    - 字段 key 存在但值为空 / N/A → 标注"该字段暂无数据"
    - 字段 key 完全不存在于返回结果中 → 不罗列、不展示
- ⚠️ **收入查询字段全量传入**：用户问"收入"相关时，target 必须一次性带上「总收入、会员收入、广告收入、分销收入、发行收入、IP增值收入、其他收入、新ROC2（vv）、新ROC2（ul）」全集，禁止只传"总收入"或"ROC2"少量字段
