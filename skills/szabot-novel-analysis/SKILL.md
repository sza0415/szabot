# 小说/剧本分析 Skill

## 快速开始

```bash
# 验证环境
env | grep TAI_IT_TOKEN
mcporter list szabot_novel_analysis
```

## 功能清单

| 服务 | 工具 | 用途 |
|------|------|------|
| `szabot_novel_analysis` | `TransferFile` | 文件转存到 COS |
| `szabot_novel_analysis` | `CreateNovel` | 创建小说并触发分析 |
| `szabot_novel_analysis` | `AddScriptInfo` | 触发剧本分析 |
| `szabot_novel_analysis` | `GetProjList` | 检索影库剧本项目 |
| `szabot_novel_analysis` | `CountWordsFromCOS` | 统计字数（按集拆分，用于判断长短剧） |

## 用途与限制

**适用场景**：
- **小说分析**：上传 → 转存 COS → 创建小说触发 AI 分析
- **剧本分析**：上传 → 转存 COS → 提取项目名 → 检索项目 → 触发分析

**支持格式**：`.doc`、`.docx`、`.pdf`、`.txt`

### ⛔ 禁止事项

1. **禁止向用户展示 file_parse 结果** — AI摘要/剧情概要仅用于内部预测赛道，**绝对不能输出给用户**
2. **禁止向用户展示 Step 执行过程** — 不要输出「Step 1：上传文件」「Step 2：转存 COS」等技术细节
3. **禁止向用户展示技术参数** — fid、file_storage_id、项目ID 等内部参数不展示（但「剧本版本」需要展示）
4. **禁止展示「剧情概要」「摘要」「内部参考」等内容** — 这些是 file_parse 返回的内部数据
5. **禁止展示字数统计** — 不要输出「字数统计：7087 字」，也不要写「长剧（字数≥6000）」，直接写「长剧」或「短剧」

**字数统计方法**：调用 `szabot_novel_analysis.CountWordsFromCOS` 服务进行统计（入参为 `szabot_fid` 和 `file_name`），该服务从影库下载文件后按「第X集」格式自动拆分文本统计中文字数，根据返回的 `avg_char_count`（集均字数）判断类型（≥6000字为长剧，<6000字为短剧）

6. **确认界面标题用「初步分析」** — 不要用「剧本分析结果」
7. **多项目必须分别触发** — 用户选择「分别分析」时，N 个项目必须调用 N 次 `AddScriptInfo`，不能只调用一次
8. **合并项目时禁止硬编码参数** — `belong` 和 `public` 必须从检索结果中获取，禁止硬编码 `public: false`
9. **session_id 不能为空** — 每次调用都必须传有效的 `session_id`，即 OpenClaw 会话标识符（`agent:main:xxx`）中的 UUID 部分
10. **禁止使用数字选项** — 所有用户选择场景**严禁使用数字列表**（如「1. xxx」「2. xxx」），必须使用文字选项，用户回复文字而非数字

> ⛔ **本 Skill 不适用于**：视频分析、代码编写、通用文件操作、项目创建、非小说/剧本文档处理。

## 依赖技能

| 技能 | 用途 | 调用时机 |
|------|------|----------|
| `szabot-file-uploader` | 上传文件获取 `fid` | 文件上传阶段 |
| `szabot-file-parser` | 解析文件获取摘要，用于预测赛道 | 长剧赛道预测阶段 |

### 文件上传

**必须调用 `szabot-file-uploader` 技能**上传文件获取 `fid`：

```
用户文件 → 调用 szabot-file-uploader → 获取 fid → 继续后续流程
```

### 赛道预测（长剧专用）

**必须调用 `szabot-file-parser` 技能**解析文件获取摘要，用于预测赛道：

```
fid → 调用 szabot-file-parser → 获取摘要 → 根据摘要预测赛道
```

> ⚠️ `szabot-file-parser` 解析结果**仅用于内部预测赛道**，严禁向用户展示。

## 文件类型判断

**根据文件名关键词自动识别**：

| 关键词 | 判断为 |
|--------|--------|
| 含「集」「一卡」「全集」「定稿」 | **剧本** |
| 不含上述关键词 | **小说** |

> 示例：《霸总第1集》→ 剧本，《霸总》→ 小说

---

## 意图识别

**判断规则**：
- 用户发送文件 + 明确说"分析小说" → 检查文件特征是否一致
- 用户发送文件 + 明确说"分析剧本" → 检查文件特征是否一致
- 用户**仅发送文件**（无说明）→ **根据文件名关键词自动分类**，剧本走剧本流程，小说走小说流程

### ⚠️ 文件特征与用户指定不一致时

当用户明确指定分析类型，但部分文件名特征与指定类型不符时，**必须提示用户确认**：

**示例场景**：用户上传 3 个文件 + 说「剧本分析」
- 《霸总第1集》→ 含「集」→ 剧本特征 ✅
- 《甜蜜爱情》→ 不含关键词 → 小说特征 ❌
- 《总裁宠妻》→ 不含关键词 → 小说特征 ❌

**询问模板**：
```
收到 {N} 个文件，其中 {M} 个文件（《A》《B》）不含剧本特征（集/一卡/全集/定稿），请确认处理方式：

- **全部按剧本分析** — 包括《A》《B》也按剧本处理
- **自动分类** — 《C》按剧本分析，《A》《B》按小说分析

请回复「全部按剧本分析」或「自动分类」：
```

> ⚠️ **关键规则**：文件特征与用户指定一致时直接执行；不一致时必须询问用户确认。

## 输出规范

**单文件**：

| 情况 | 输出 |
|------|------|
| 分析小说 | `收到！《{file_name}》创建新项目后开始小说分析，稍后为您推送分析结果。` |
| 分析剧本 | `收到！《{file_name}》正在检索影库项目...` |

**多文件（特征一致）**：

```
收到！共接收 {N} 个文件：《A》《B》《C》，全部进行{分析类型}。

正在处理，稍后为您推送分析结果。
```

**多文件（自动分类，无用户指定）**：

```
收到！共接收 {N} 个文件：
- 剧本（{M} 个）：《A》《B》→ 进行剧本分析
- 小说（{K} 个）：《C》《D》→ 进行小说分析

正在处理，稍后为您推送分析结果。
```

**多文件（特征不一致，需确认）**：

```
收到 {N} 个文件，其中 {M} 个文件（《A》《B》）不含剧本特征（集/一卡/全集/定稿），请确认处理方式：

- **全部按剧本分析** — 包括《A》《B》也按剧本处理
- **自动分类** — 《C》按剧本分析，《A》《B》按小说分析

请回复「全部按剧本分析」或「自动分类」：
```

**多文件（检测到多个项目，需分组确认）**：

```
📁 检测到多个项目：

📂 项目 1：豪门继承人（2 个文件）
   - 豪门继承人第1集.docx
   - 豪门继承人第2集.docx

📂 项目 2：逆袭人生（1 个文件）
   - 逆袭人生第1集.docx

请选择处理方式：
- **分别分析** - 每个项目分别触发分析
- **合并为一个项目** - 请输入统一的项目名

请回复「分别分析」或输入项目名：
```

**多文件 + 同名合并**：

```
收到！共接收 {N} 个文件：
- 《坤宁1》《坤宁2》→ 合并至影库项目《坤宁》，进行剧本分析
- 《霸总》→ 创建新项目，进行小说分析

正在处理，稍后为您推送分析结果。
```
